# STRM management UI contract

- The protected STRM route group contains `/strm`, `/strm/files/:id`, `/strm/check-results`, and `/strm/cleanup-preview`. All four screens display the demo data label. A reload or navigation out of the route group restores the initial records. See [app routes](../../../frontend/src/app/app.tsx).
- URL search parameters own filters, sort, page size, and page. The route session owns file records and per-view selection. A changed filter clears selection, while page changes and detail round trips preserve selection for the same filter. HeroUI Table handles selection for visible rows with `selectionMode="multiple"` and checkboxes with `slot="selection"`. Merge the visible page's selection into the session set so keyboard selection and select-all share the batch scope.
- Checking records the selected file snapshots, time, duration, and original listing address. Regeneration updates the current records while the results retain the findings from that check. A direct visit without a run displays a return link. See [session state](../../../frontend/src/features/strm-management/strm-session.tsx).
- Cleanup captures file IDs on entry and recomputes current eligibility at confirmation. Only files with invalid status and explicit removal eligibility contribute to confirmed count and freed space. Cancellation retains the original selection. CSV contains every matching row in the current sort order and is downloaded from the browser. These actions use local demo data through the [STRM model](../../../frontend/src/features/strm-management/strm-demo.ts).
- Browser coverage verifies keyboard selection, pagination, filtered context restoration, export, check and cleanup scope, and reload on desktop light and mobile dark. See [STRM Playwright coverage](../../../frontend/e2e/strm-management.spec.ts).

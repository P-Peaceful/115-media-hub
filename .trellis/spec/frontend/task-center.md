# Task center UI contract

- The protected routes are `/tasks`, `/tasks/:id`, `/tasks/schedules`, `/tasks/schedules/new`, and `/tasks/schedules/:id/edit`. Open the schedule list from the task center. Detail and edit routes support direct navigation and provide return links.
- The feature uses generated API types and validates network responses before populating its query cache. Overview counts and list rows use the same response. Missing metrics have an empty display. Capability results determine which types can create or update schedules, and run responses provide the allowed single-row actions.
- Use the pinned HeroUI v3 components and documented variants for cards, navigation controls, form fields, tabs, tables, dialogs, and feedback. The global HeroUI theme supplies light and dark component tokens. Keep feature styles on page layout, content arrangement, and responsive sizing.
- Keep all seven type filters visible. Display `strm` runs as 「全量同步（STRM）」 in history, details and notifications. Create these runs from media-library full sync. With no available module, show real empty results and the unavailable reason. The plan editor binds to a media library or all eligible libraries, defaults to Beijing time, and submits the appropriate fields for each cycle. Edit sends the revision from the loaded resource. Execution configuration lives in the media library. Tables present per-record actions.
- One task event listener is mounted for the authenticated application. It invalidates the pertinent task and plan queries on named SSE events and refreshes persisted data when it reconnects. Plan notification outcomes display a live toast with a task link. No external delivery channel is involved.
- Browser verification covers the production empty state, direct navigation, task detail and failure retry, scheduling of a weekly run with an injected test capability, desktop and mobile themes, and input-only plan payloads. See [task center Playwright coverage](../../../frontend/e2e/task-center.spec.ts).

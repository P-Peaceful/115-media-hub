## 验证命令

每个实现切片运行适当检查，随后执行完整交付门禁：

```bash
make generate
make check
make test-e2e
make test-integration
make build smoke
make docker-build docker-smoke
git diff --check
```

补充实际行为验证：

- 对未初始化/已初始化管理员验证初始化竞争、错误凭据、限流和密码恢复。
- 验证 CSRF 缺失/错误、跨源请求、会话固定/轮换、过期、Cookie 标志和受保护管理路由。
- 验证后端重启后持久化、重置/登出撤销，以及必要审计失败时的事务回滚。
- 验证前端错误响应/网络/重试/字段错误、外部返回地址拦截、缓存清理、过期/重新聚焦和键盘表单行为。
- 确认数据库审计、日志和浏览器存储中均无明文密码/原始会话/CSRF 值。
- 验证嵌入式二进制和容器中的静态资源/健康检查/API 命名空间行为。

模拟浏览器和真实后端模式都必须通过；模拟认证测试成功不能证明真实集成可用。Docker/浏览器/工具链检查不可用时，应如实记录，不能当作通过。

## 风险与回滚点

- 凭据结构、Cookie/CSRF 和本地恢复需完成跨层评审后，才能认定登录可用。
- 不要盲目修改现有健康检查浏览器测试；迁移路由时保留其 API 覆盖。
- 真实后端初始化需隔离，或明确串行执行。
- 未来媒体输出前，必须将宿主机目录挂载到容器内 `/app/media` 并确认可写；本任务仅保存该路径，不生成文件。Docker 的数据库、日志、缓存、备份和隔离目录也使用 `/app/` 下的容器目标；本地开发数据库仍位于项目 `backend/data/`。
- HTTPS 经代理公开时，需要说明 Secure Cookie 配置。
- 使用一致性备份和匹配版本二进制回滚已部署凭据数据；不得把破坏性降级伪装成回滚。

# 管理员登录与首次初始化

## 目标

参考用户提供的 `/home/wenzhengcheng/下载/登录.png` 及明确提出的视觉删减要求，为 115 Media Hub 提供可用的管理员认证和首次初始化流程。

## 背景与已确认决策

- 用户已批准创建并规划任务，并确认登录相关页面移除 115 授权、移除整个顶部状态栏/标题栏，并通过服务器本地命令恢复密码。2026-11-08，用户拒绝兼容旧数据库结构，并自行删除旧数据库；密码最长 32 位，只接受常规非中文字符。
- 现有代码已实现应用启动、SQLite 迁移、公开健康检查和 React 健康页面，尚无认证和业务设置。
- 项目基线要求单一管理员、密码哈希、Cookie 会话、CSRF 防护和数据库业务设置。
- 用户于 2026-11-07 明确批准最终规划摘要；之后先将默认输出目录调整为 `/media`，最新又要求统一使用 `/app/media`。实现已获授权。

## 需求

### R1 — 视觉体验

- 交付高保真的中文登录和初始化页面，字体、面板比例、间距、渐变、阴影、图标、输入框/按钮尺寸和媒体文件夹插画应贴合参考图。先应用用户明确要求的删减，再做视觉对比；布局需适配移动端。
- 两个页面都不显示顶部状态栏/标题栏：不显示顶部品牌、任务计数、通知按钮或管理员菜单。品牌标识保留在登录主内容中。独立主题切换按钮放在视口右下角。参考画板中的说明文字属于设计标注，不得展示在产品中。
- 完全移除 115 授权卡片和入口。重排初始化页其余内容，不留空占位或预留空间。
- 提供无障碍标签、键盘交互、密码显示控制，以及明确的校验、加载和失败状态。支持跟随系统的亮/暗主题，并使用 HeroUI 官方 React 主题 API 提供持久化的手动切换。

### R2 — 首次初始化

- 未初始化的部署进入初始化页。收集管理员用户名、密码、确认密码、登录有效期、公开服务 URL 和服务器默认输出目录。
- 当前默认值：有效期可选 1、7、30 天（默认 7 天）；公开服务 URL 预填当前源；媒体输出路径为 `/app/media`。Docker 部署的数据库、日志、缓存、备份和隔离区挂载目标均位于 `/app/` 下；本地开发数据库继续保存在项目目录 `backend/data/`。
- 输出目录是以文本填写的服务器绝对路径。不得加入文件系统浏览器，也不得暗示客户端目录选择会配置服务器。
- 服务端校验所有字段，并提供一致且有帮助的客户端校验。以原子方式保存管理员和设置。重复或并发初始化不得覆盖现有数据。
- 初始化成功后创建认证会话并进入受保护的首页。初始化完成后不可再次访问初始化页。

### R3 — 登录与认证导航

- 使用用户名和密码认证；凭据错误时显示统一且安全的提示。阻止重复提交，并限制重复尝试次数。
- “记住登录”复选框控制使用持久 Cookie 还是浏览器会话 Cookie。两种情况下服务端都会执行配置的固定有效期。参考图的会话说明应准确描述过期行为，不承诺未定义的闲置超时。
- 登录后只保留有效的站内返回地址，排除认证页面以及不安全/外部地址。没有返回地址时进入 `/`。
- 保护应用首页和未来的管理端点，提供登出，并在会话过期/撤销后返回登录页。登出/过期时清理受保护缓存。
- 仪表盘尚未实现时，保留现有健康页面作为认证后的首页，并提供可用的登出操作；不得虚构仪表盘模块或任务计数。

### R4 — 密码恢复

- 用户已确认：提供服务器本地管理员密码重置命令，并在“忘记密码”入口中展示使用说明。不提供邮件恢复。
- 初始化、登录和恢复密码都必须为 8–32 个可打印、非空格 ASCII 字符（U+0021–U+007E：英文字母、数字和标点）。拒绝中文/非 ASCII、空格和控制字符；保留原始输入，不裁剪，也不要求字符类别组合。恢复密码不得出现在进程参数、URL、环境变量或日志中。支持有文档说明的容器操作。
- 只重置已存在的管理员密码；原子撤销所有现有会话，并保留初始化和应用设置。数据库未初始化时拒绝恢复操作。

### R5 — 安全、持久化与可观测性

- 只存储密码哈希和不透明会话标识的哈希；不存明文密码或原始会话密钥。使用 HttpOnly Cookie、明确的 SameSite 策略，并在 HTTPS 部署时启用 Secure。
- 初始化、登录和登出均实施 CSRF 防护；拒绝无效/缺失令牌及跨源的状态变更请求。认证密钥不得进入浏览器存储或日志。
- 会话在应用重启后继续有效，直至过期/撤销。不得通过公开健康检查/初始化状态响应暴露设置、管理员身份或会话密钥。
- 为初始化、凭据/会话变更和密码恢复保存审计记录；记录可归因的登录结果及限流事件，但不包含密钥。方案中定义审计写入失败时的行为。
- 保留现有公开健康路由、非 2xx 错误封装、请求关联、SPA/静态资源命名空间语义和部署架构。不得实现旧开发认证数据库结构兼容；用户已明确选择并自行删除/重建本地数据库。正常启动时绝不自动删除数据库。

### R6 — 组件优先级、API 时效性与代码质量

- 用户明确要求：所有适用的前端组件优先使用 HeroUI。标准控件和交互模式使用锁定版本 v3 中受支持的组件；选用 API 前查阅官方文档。语义化 HTML/CSS 仅用于布局/内容或缺少合适组件时，并在评审中解释必要的替代方案。
- 用户明确要求：新增或修改的前后端代码不得使用已弃用的方法/API。对照锁定依赖和工具链版本的官方文档确认 API 状态，不复制过时示例，也不能仅凭编译通过认定 API 仍受支持。不得只为追新而升级依赖。
- 用户明确要求：前后端代码可读并符合单一职责。区分传输层、用例策略、持久化、API 访问、状态编排和界面展示；使用清晰命名及职责内聚的函数/模块，不做推测性抽象。
- 交付前对照用户提供的参考图检查桌面/移动端视觉，并修正明显偏差。运维测试不能证明视觉还原度。

## 不在范围内

115 授权/连接管理及相关卡片/占位内容；邮件/短信恢复；注册/多账户；账户/设置编辑页面；文件系统浏览；仪表盘/业务模块；任务/通知界面；基于闲置时间滑动续期的会话策略；旧开发数据库结构兼容。

## 验收标准

- AC1（R1）：两页在桌面和移动端符合调整后的视觉方向；不包含已移除的顶栏、授权入口、占位空隙或画板标注。
- AC2（R2）：全新数据库进入初始化；有效初始化保存唯一管理员/设置并完成登录；无效数据和并发初始化均不能产生部分状态或替换管理员。
- AC3（R3）：有效凭据可登录；错误凭据按约定提示；重复尝试会被限流；记住登录会改变 Cookie 持久性，同时服务端有效期仍然生效。
- AC4（R3）：刷新页面和重启后端后有效会话仍可用；登出、过期和重置都会阻止受保护请求。保留同源站内返回地址，拒绝恶意/外部地址。
- AC5（R4）：本地恢复可替换密码、拒绝旧密码、撤销所有现有会话并保留设置；提供二进制和容器用法文档；忘记密码入口展示真实操作说明。
- AC6（R5）：缺失/错误 CSRF 和跨源状态变更请求会失败；HTTP 开发与 HTTPS 部署的 Cookie 标志正确；日志和浏览器存储不含密钥。相关审计记录和失败处理均经过测试。
- AC7（R1–R5）：表单覆盖校验、提交中、网络/服务端错误和会话过期状态；键盘操作、密码显示、亮暗主题和窄屏布局可用。
- AC8（R5）：现有健康检查、SPA 和迁移行为（包括全新标准结构及正常迁移/重启）通过回归检查；OpenAPI 与 Go/TypeScript 生成类型一致；真实前后端集成和生产嵌入构建通过。
- AC11（R4）：初始化、登录和 CLI 恢复一致接受 8/32 字符 ASCII 边界及标点，拒绝 7/33 字符、中文/非 ASCII、空白和控制字符；无效输入不得被静默裁剪或截断。
- AC9（R6）：评审确认标准前端控件由 HeroUI 提供；新增/修改 API 在锁定版本中仍受支持且未弃用；命名清晰，层、组件和模块职责聚焦。
- AC10（R1、R6）：已保存的桌面/移动端截图均与调整后的参考图对比检查字体、比例、插画、间距、渐变、阴影和交互状态；明显偏差已修正，剩余限制有明确记录。

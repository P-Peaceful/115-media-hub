## 运维说明

HTTPS 在反向代理终止时，需要设置 `MEDIAHUB_COOKIE_SECURE=true`。仅配置输出路径不代表目录一定可写，也不会生成媒体文件；Docker 现已提供默认输出目录/卷。凭据迁移的 Down 操作有意拒绝；回滚数据必须使用一致性备份和匹配的二进制。生产包有一条不阻断构建的主 JavaScript 体积提示（约 592 KB 未压缩、185 KB gzip）；所有功能门禁通过，未屏蔽该提示。

所有临时诊断服务器和隔离测试容器均已停止/移除。代理未更改用户凭据或迁移在线数据库；之后用户自行删除并重建了旧数据库，详见下文。工作仍未提交，位于 `codex/admin-auth` 分支，等待仓库要求的显式批量提交评审；批准提交后再按流程归档任务/完成日志。

## 后续：本地 bootstrap 持续返回 503

用户报告打开本地浏览器后持续出现 503。主代理复现了 `/health/live` 和 `/health/ready` 返回 200，但 `/api/v1/auth/bootstrap` 经直连 8080 和 Vite 5173 均返回 503。只读检查运行中的 GoLand 进程默认数据库 `backend/data/mediahub.db` 发现 goose 已记录版本 2，但结构仍为旧版本：管理员表无单例约束，`system_settings.session_days`，以及 `auth_sessions`、`security_audits`。检查时这四张表均无数据。此前全新数据库/从版本 1 升级的测试没有覆盖“版本号已为 2，但表结构与当前版本不同”的情况。执行在线迁移前，曾创建并验证一致性 SQLite 备份 `backend/data/backups/pre-auth-schema3-20261108-010215.db`；临时备份被忽略且权限为 0600，用户明确决定删除旧数据库后已移除。用户明确拒绝兼容并自行删除/重建数据库。任何在线迁移前，兼容迁移 3 及其测试/注册代码已移除。之后只读验证直连 8080 和 Vite 5173 的健康检查/bootstrap 均返回 200（`initialized=true, authenticated=false`）。保留的改进增加安全的存储操作诊断，并将已取消的 bootstrap 视为取消任务，而非伪造 503/ERROR。新密码策略为 8–32 个可打印非空格 ASCII 字符；完成的后续门禁见下文。

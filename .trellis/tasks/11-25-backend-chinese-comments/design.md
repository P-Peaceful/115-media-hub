# 中文注释设计

## 边界

覆盖 backend 下所有手写 Go 文件，包括测试和构建变体。遵守 `.trellis/spec/backend/quality-guidelines.md`：生成文件不手改，注释聚焦职责、原因、约束和生命周期。

## 文件说明

普通文件在 package 前放置简洁中文文件职责说明。每个文件说明其实际分工，不把同一个包文档复制到所有文件。已有 package 文档在保留正确包名标识的同时使用中文；其余文件使用“文件名：职责”式说明。构建变体保留 go:build 在文件最前部及其必要空行，职责说明放在指令块之后、package 之前。

## 方法与重要声明

导出声明注释以对应标识符开头，随后用中文描述。私有主流程、并发控制、分页/编解码/安全校验、SQL 持久化与文件发布恢复等应解释其目的和重要边界。方法注释不逐行翻译实现，不声称代码没有实现的重试、加密或可靠性机制。

测试文件解释被测模块，测试方法说明场景和预期结果；通用辅助方法按其必要性说明资源清理、断言边界等。

## 兼容与验证

只改注释和必要格式。以 Go parser 解析修改前后源码，去除注释后比较 AST；另外比较所有构建/生成/embed/链接等工具指令，防止 AST 未体现的差异。确认 build tag 的格式与空行。覆盖检查不能证明注释语义，必须按模块人工复核。

## 协作

按入口/app、HTTP、service、repository/domain/migrations/web 分批处理。派发时明确文件所有权，提醒 worker 不是独占代码库，不得回退其他人的更改。实现与质量检查遵循 Trellis 子代理流程。不要让注释任务与 SDK 任务同时写相同文件。

## 回滚

注释交付独立于业务改造提交；若检查发现行为变化，恢复该项非注释差异，不覆盖工作区其他修改。SDK 后续重构必须为新增代码同步补中文说明。

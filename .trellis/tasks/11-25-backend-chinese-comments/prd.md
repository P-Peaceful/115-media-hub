# 补全后端 Go 中文职责与方法注释

## 目标

让维护者通过文件开头和主要方法的中文注释，理解后端职责、调用边界、关键约束和副作用。来源为用户 2026-11-25 第一项需求。

## 背景

当前有 83 个 Go 文件，其中 82 个手写文件（含 26 个测试文件），1 个为 backend/internal/http/generated/types.gen.go 生成文件。存在英文说明、无文件说明及主要方法缺少说明的问题。清单见父任务 research/backend-inventory.md。

## 范围与要求

- C-R1：覆盖 backend/**/*.go 的所有手写文件，在合法的文件开头位置补中文职责说明，描述文件本身的职责。
- C-R2：所有导出函数/方法和主要私有函数/方法补中文注释；按需交代输入约束、返回语义、副作用、错误及资源生命周期。
- C-R3：类型、接口、常量和字段在涉及公共合同或关键不变量时补中文说明；保留准确说明，纠正过时内容。
- C-R4：测试文件说明测试对象和覆盖边界；测试方法解释验证的行为/回归问题，不给机械辅助函数堆积无用说明。
- C-R5：重点说明认证/CSRF、任务调度/取消、分页身份、文件所有权、写入恢复和脱敏等真实已实现约束，禁止虚构保证。
- C-R6：遵循 Go 文档命名，保留 go:build、go:embed、go:generate 等指令语义与必需空行；区分文件说明和包文档。
- C-R7：仅改注释及必要格式，不改函数签名、控制流、SQL 或 HTTP 合同。生成文件遵循现有规范，不直接手改。

## 验收标准

- C-AC1：82 个手写文件均有中文文件职责说明；文件变化时刷新清单。
- C-AC2：导出函数/方法和主要私有方法有准确中文说明；自动覆盖统计配合人工内容评审。
- C-AC3：比较变更前后不含注释的 Go AST，证明声明和运行语义不变；单独核对编译指令和指令空行。
- C-AC4：make -C backend format-check 和 make -C backend vet 通过；不为纯注释改动新增应用测试，其余门禁按实际风险记录。
- C-AC5：生成文件没有手工差异，不加入敏感信息示例或不可证明的安全承诺。

## 不包含

业务修复、重命名、重构、接口改变、依赖替换、直接手改 types.gen.go。

## 执行协调

先于 SDK 子任务完成；SDK 新增/改动代码同步遵守中文注释要求，父任务最后交叉验收。

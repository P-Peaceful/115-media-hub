# 父任务协调设计

## 交付边界

本任务只负责协调和验收；产品实现由两个子任务承担。用户已选择 SDK 方案 A，最终摘要批准后依次激活子任务，不激活父任务进行产品改造。

## 顺序与所有权

先对后端手写 Go 文件补中文注释并证明运行语义不变，再改造 Cookie SDK，最后接入媒体库附属同步。三项分别提交；新增文件和重构方法继续符合中文注释规则。附属复用扫描清单，先有同目录视频对应的有效 STRM 才下载；已有附件跳过，图片不按命名过滤，最终验收遵循第三子任务设计。

实现与检查默认使用 Trellis 子代理。派发时首行使用实际 Active task 路径，明确文件所有权，要求加载对应计划/spec；提醒代理并非独占代码库，不得回退他人更改。父会话负责用户沟通、决策、集成、spec、提交和完成记录。

## 跨任务不变量

生成文件不手改；构建工具指令保留；Cookie、目录公共分页、产物所有权/凭证和播放 URL 保持兼容。预览改为有预算的少量目录抽样，确认后完整扫描；同步更新 API、生成类型与前端提示，不把抽样计数当全库总量。SDK 不引入 OAuth、事件增量或网盘写功能，不扩大为第三方产品复刻。

## 验收与风险

注释交付检查覆盖与去注释 AST/指令，SDK 检查限速/取消/冷却、快慢等价和产物回归。父任务核对最终新代码同样具备中文注释，并确认所有适用项目门禁与实际环境限制已记录。非公开快速接口变化通过受控标准扫描降级与运行开关处理，不宣称免风控。

用户最初要求先规划；规划收敛后于 2026-11-25 明确要求“开始所有任务”，批准 planning-review.md 的最新完整方案。按注释、SDK、附属同步顺序执行。

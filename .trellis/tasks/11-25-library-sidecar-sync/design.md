# 媒体库附属文件同步设计

## 1. 范围与前置

在注释、Cookie SDK 两项交付后实施，沿用媒体库全量同步入口和配置快照。先处理视频 STRM，只有相同源目录中至少一个视频的 STRM 新建成功或已验证同源有效，才允许该目录的附属下载。NFO 开关决定 .nfo，图片开关决定 .jpg/.jpeg/.png/.gif/.webp/.bmp（大小写不敏感）；符合上述前提后，图片名称不限。不增加字幕、刮削、转码或上传。

用户已决定所有本地同名普通文件跳过，STRM overwrite 不控制附属。只传输远端原始字节，保留原名/相对目录。图片与 NFO 不加入 STRM 登记，也不改变 STRM 列表和媒体库 STRM 数量。

## 2. 分层与扫描复用

- provider adapter/service 提供下载描述（源账号/文件身份、可信临时目标、必要 UA/头）和可取消内容传输。复用 SDK 账号配额、错误分类及依赖注入，不暴露临时链接到前端。
- strm 同步服务负责候选筛选、源身份、输出映射、临时文件与排他发布、意图恢复和分类结果。提取真正共享的安全目录/发布辅助方法，保留 STRM 专用的后缀和内容校验；不得简单取消其 .strm/16 KiB 限制。
- sqlite 只负责新下载意图的短事务/条件更新，网络和文件传输在事务外进行。
- task center 继续登记条目与终态；前端只调整与附属结果/说明直接相关的展示，不增加单独下载管理页。

标准扫描与快速快照均在一轮枚举中分别收集视频、NFO、图片；目录排除、递归、账号检查和完整性共用。快速结果完整后采用，标准结果仍以完整目录为提交边界，失败目录中的附件不下载。预览仅在同一抽样结果中说明启用的同步类型，不取附件直链、不拉内容、不额外列目录，四项预算不变。

扫描时保留视频与附件的 source directory ID/输出相对目录。先执行 STRM 生成/既有内容验证，按成功或可验证同源跳过结果建立 eligibleDirectories，再安排附件；发现视频本身不产生资格。父/子目录不互相继承资格，视频全失败/冲突的目录不进入下载队列。存在外部 .strm、仅登记但本地缺失、用户改动或失配来源的文件均不算可用 STRM。下载准入及发布前复核对应目录仍有同源有效 STRM，避免依赖已被删除/改动的文件。

## 3. 已有文件和下载发布流程

1. 先核对同目录有效 STRM 资格，再解析安全相对路径，按现有 rooted directory/身份检查创建或打开目标目录；每个路径段合法，拒绝末级符号链接、目录或其他非常规目标。无资格记录跳过原因，不发取链/内容请求。
2. 已有普通文件直接记 skip，零取链/下载，不读取其内容、不核对远端版本。不存在时以 target_path 唯一保留一条下载意图，防止不同任务同时发布。
3. 在目标同目录创建随机临时文件（O_EXCL、受控前缀），记录临时名字和文件身份。意图登记与文件创建各自短操作，失败立即停止本条，不抢占别人的目标。
4. 通过受限流的 API 取链，核对账号与源文件，按下载描述请求可信目标，把响应流写入临时文件；检查大小、HTTP 状态和已知长度，取消/截断/超限不发布。
5. 写完 Sync/Close，在持久化意图中标记完整暂存；重新检查凭据、目录绑定、同目录 STRM 资格和目标。用不可覆盖的原子发布（同目录 Link 或等价 no-replace 操作）将完整暂存发布为最终文件，再 sync 目录。
6. 发布竞争时若普通文件已经出现，保留对方文件并记 skip；异常目标报告冲突。登记实际任务结果后移除意图及本条仍持有身份的临时文件。

下载期间不长期持有全局 outputMu 或数据库事务；临时目标保留/最终发布使用短临界区及数据库唯一约束。已存在文件永远不因来源不同、远端大小变化或配置 overwrite 而被覆盖。关闭开关和删除媒体库均不删除已下载正式文件。

## 4. 持久化与中断恢复

新增独立 sidecar_download_intents 表，不复用 strm_artifacts/strm_write_intents。最小记录包含 intent ID、job/attempt、library/account/source ID、源类型、output root/relative target、临时 basename、临时文件身份、状态和预期/已完成字节数及时间。target_path 唯一，状态有限且受条件更新；不存 Cookie、临时 URL 或内容正文。

阶段为 reserved → staging → staged → published；每个转换只表示已验证完成的事实，文件动作在事务外。完整任务结果仍由 task items 持久化，本轮不新增附件浏览/覆盖/清理台账功能。

恢复先处理本库下载意图，再开始新候选。最终目标已存在的普通文件一律保留，报告恢复后跳过，不因恢复而接管其内容或称其由本次新下载。目标不存在时不采用未发布旧临时内容，核对意图/目录/临时身份后清理本应用仍可证明拥有的临时文件并重新下载；无法证明临时身份时保留并报告冲突，不靠名称前缀扫删文件。发布成功但任务结果尚未登记时，重新运行仍遵守 skip 规则，不重复覆盖或误报新写入。

恢复阶段不直接重启附件下载。先处理意图安全状态，之后待本轮 STRM 建立同目录有效资格再按正常队列决定是否下载；无资格只清理可证明属于本应用的暂存，保留已有正式附件，不补下载。

新增 goose 迁移；不修改既有已应用版本。Down 在仍有意图时拒绝，要求一致性备份/核对后再回退；空表可安全移除。测试新库与前版升级。SDK 子任务自身仍无需迁移，迁移属于本子任务。

## 5. 请求与下载限制

取链走 SDK 统一账号间隔（默认完成后至少 1 秒）和共享冷却；传输完取链响应即可释放 API 配额，不把文件内容下载长时间占为账号 API 锁。

内容下载按账号共享最多 2 个并发，跨库/任务也共用该上限，队列有界。初始技术限制：NFO 每文件最多 8 MiB、图片最多 64 MiB；每个文件从实际处理开始总预算 120 秒（含取链、重试/冷却），单次内容传输最多 30 秒，仍服从更早的任务取消。使用流式写入，不按文件上限预分配内存；有已知源大小时提前拒绝超限，实际传输再以 limit+1 检查，长度不符失败。

内容请求最多 3 次尝试（含首次），临时网络/502/503/504 使用 1 秒、2 秒退避。429 遵守 Retry-After；无有效值默认冷却 30 秒，同账号/下载源等待者共用冷却，剩余预算不足则返回真实失败，不能缩短上游冷却。403 不直接视为授权失效；仅在协议证据明确为链接过期时允许重新取链一次，并受既有 API 尝试/账号间隔和文件总预算约束，内容尝试总数不增加。

内容请求使用受控下载 UA/必要头，不借用用户管理员会话或播放器客户端上下文。每跳重定向核验 HTTPS、可信域和目标地址，跳数有界；凭据不得转发到未经允许的域。保持标准 TLS；不将签名 URL 写进错误、日志或数据库。账号更换时停止采用旧响应，取消等待与传输并释放并发配额。

## 6. 条目、统计与前端

同一全量任务内条目键分为 file:<fid>（现有 STRM）、sidecar:nfo:<fid>、sidecar:image:<fid>，不改变既有 STRM 来源身份。通用 total/succeeded/failed/skipped 表示全部处理项；终态业务日志和任务日志分别列 STRM、NFO、图片的成功/跳过/失败数量，前端沿用真实任务条目/日志，不把通用成功数标成 STRM 数量。

单附件失败独立登记，继续处理其他项；总结果依现有框架计算成功/部分失败/失败。重复执行只跳过已有附件，不重写成功 STRM；不新增“失败项专用重试”或暂停能力，沿用当前模块的整轮重跑和取消合同。前端配置可补充说明“同步网盘已有文件”，不把功能描述成缺失文件刮削。

如需要调整 HTTP 合同，先改 OpenAPI、生成类型，再改两端消费者；不为固定分类计数预建新的统计服务。不把图片/NFO 的二进制内容写入 JobLog。

## 7. 验证与回退

验收矩阵见 PRD/执行计划。重点覆盖无视频/同目录 STRM 不可用时零附件请求、先 STRM 后附件、父子目录资格不继承、同名文件零请求、发布竞态、取消与长度错误、意图各阶段中断、限流和跨任务并发、快慢候选一致、预览零下载、任务统计及原 STRM 恢复/302。

关闭库的 NFO/图片开关即可停止相应新下载，已有文件保留。代码回退保留用户正式文件；迁移回退遵守意图保护。真实下载验证独立于模拟，不能将非公开接口模拟成功称为实盘已通过。

# 115 Cookie 客户端改造设计（方案 A）

## 1. 范围与兼容边界

用户选择 A：改造现有 Cookie 请求底层、节流、冷却重试、错误分类和扫描能力。保持单账号、明文凭据存储既有选择、扫码方式、目录浏览 API、正式任务生命周期、STRM URL/所有权/写入恢复和 302 目标校验。预览改为有预算的少量目录抽样，相关接口说明与 UI 同步更新。

不引入 OAuth、事件增量、多账号、网盘写操作或新设置页面；不复用预览缓存。现有 m115 编解码依赖保留，目录和授权不改用第三方 driver。无数据库迁移；先更新抽样预览 OpenAPI 合同，再生成 Go/TypeScript 类型及修改消费者，不手改生成文件。

## 2. 分层与受影响位置

- `backend/internal/adapter/provider115/`：新增小型外部协议适配层，拥有 HTTP 传输、端点配置、请求分类、节流/冷却/重试、响应边界及上游 DTO。不得依赖 Gin、GORM、library、strm 或 repository。
- `backend/internal/service/provider115/`：保留账号/扫码状态机、凭据读写与变更校验、公开查询校验、上游数据投影及业务错误映射。为内部扫描提供较大分页与树快照能力，不通过公共 FileQuery 绕过分页限制。
- `backend/internal/service/strm/scan.go`：选择快速或标准扫描，将可信源条目交给既有 sourceVideo、路径/排除和文件所有权流程。采用清单前校验完整性，报告进度与失败。
- `backend/internal/app/config.go`、`app.go`：构造并注入客户端与策略，不使用包级可变全局客户端或 limiter。保留当前调用方的便利构造，测试可注入端点、RoundTripper、时钟/等待行为。
- `.env.example`、README：仅增加运行参数说明；不新增前端配置流程。
- `api/openapi.yaml`、`frontend/src/features/media-library/full-sync-preview-query.ts`、`library-execution-preview-page.tsx`、`library-full-sync-preview-results.tsx`：限定于抽样预览语义、响应校验、计数标签、停止原因、空结果和确认资格，不扩大成前端改版。

账号业务读取、目录、播放、扫码共用传输机制；按业务操作标识控制策略。扫码域不挤入文件扫描节流，登录交换不自动重试；播放取链虽用 POST，仍属于可重复读取的独立声明操作，不能按 HTTP 方法推断写入语义。

## 3. 请求与凭据生命周期

1. Service 校验输入，读取凭据快照及账号身份。
2. Adapter 为声明的只读操作申请账号配额，等待/发送均继承 context；每次尝试重新构造 body，保留播放器 UA（包括空 UA）。
3. 拒绝非允许的生产端点和重定向，维持标准 TLS；测试仅通过注入端点使用 httptest。
4. 读取有大小上限的响应并及时关闭 body，分类状态/协议错误，按策略决定冷却或重试。
5. Service 在采用响应及扫描批次前检查当前凭据仍与快照一致；替换、解绑后不返回旧结果，重试不能悄悄换成新账号。

账号冷却键使用内存中的不透明账号作用域，不使用原始 Cookie 作为日志标签。相同账号更新 Cookie 不清除已有冷却。旧凭据响应会被废弃；不得逐次创建新 limiter 来逃避已生效的冷却。

## 4. 限速、调度与配置

默认所有文件/账号只读请求共用账号准入，完成上一请求后至少等待 1 秒；串行准入包含整个请求生命周期。配置 `MEDIAHUB_115_REQUEST_INTERVAL`，默认 `1s`，接受 `1s`–`60s`，支持调大且不封顶回 1 秒。非法配置使启动失败，错误明确且不含凭据。扫码操作按既有状态机与期限执行，不为未实现写操作建立调度框架。

播放和普通交互读取优先于后续后台分页，但不能抢断已在途请求，所有文件类读取遵守同账号冷却。后台每页重新准入，不持有整轮扫描的配额锁。并发竞争时采用有界公平规则，最多连续放行 4 个前台请求后应给已等待的后台请求一次机会；没有后台等待时不限制前台连续服务。等待无独立常驻 goroutine，不泄漏已取消队列项，关闭与调用方取消可释放所有等待。

播放操作总预算维持短路径（上限 15 秒或调用方更早期限）；一般元数据/目录操作预算上限 45 秒、每次在途请求上限 15 秒。等待、退避和尝试均计入总预算；抽样预览使用已确认的 15 秒独立总期限。通过可控时钟/信号验证，不依赖真实长 sleep。

## 5. 错误、重试与冷却

内部错误保留受控 operation、kind、HTTP 状态和可用 retry time，Error 文本不包含请求 URL、响应原文、Cookie 或 pickcode。kind 至少区分 canceled/deadline、invalid_authorization、not_found、throttled、temporary 和 protocol。保留 errors.Is/As 身份；Service 继续映射既有 ErrUnconfigured、ErrInvalidAuthorization、ErrDirectoryNotFound、ErrUpstream，对外保持现有 409/404/503 合同，不新增公开错误码。

| 情况 | 处理 |
| --- | --- |
| 明确未登录/无效凭据、404 源不存在 | 不重试，不切端点，不做快速到标准重扫。 |
| context 取消/期限 | 立即停止等待和请求；保持取消身份，不降级。 |
| HTTP 429 或有依据的业务限流码 | 设置账号共享冷却，遵守 Retry-After 秒值/HTTP 日期。没有有效头时按 30 秒冷却；本轮预算不足则返回限流，冷却仍保留。 |
| 可恢复网络故障、502/503/504 | 只对明确只读操作最多尝试 3 次（含首次），退避 1 秒、2 秒；退避与全局间隔共同约束。 |
| 格式异常、超大响应、身份不符 | 返回协议/身份错误，不无界重试。快速枚举仅按第 7 节规则进行一次标准回退。 |

Retry-After 不因本地上限而被缩短。不可表示的异常长值直接阻止本轮重试，并记录受控错误；不得以立即 fallback 或换域名绕过冷却。限流是否有第二次尝试由调用预算决定，不承诺所有操作都会等待 30 秒。

响应上限按协议设定：保留扫码/普通账号读取的现有限制、播放 64 KiB；为 1150 文件页和 5000 目录页设置独立的有界响应上限（初始 4 MiB、8 MiB）。分页次数、总数、重复页和祖先深度都有防循环约束，不把超界截断当作清单完成。

## 6. 公开浏览与标准扫描

公开 Files 继续验证 limit 1–200、page/cursor 互斥、绑定过滤条件和安全整数，保留 custom_order/cur 等已验证排序参数。DTO、过滤/排序、total/page 语义不变。

内部标准扫描使用独立入口，批次目标 1150；只在明确不支持该批次时改用既有 200 条路径，不因限流直接缩小批次并继续打接口。仍逐目录串行，完整读完一个目录后才采用其候选；兄弟目录部分失败策略、账号一致性、去重、循环 cursor 防护与根目录回退校验保持现状。非递归库使用标准方式，不先拉整棵树。

## 7. 快速扫描与安全降级

递归库默认先尝试快速扫描，通过 `MEDIAHUB_115_FAST_SCAN`（默认 true）可整体关闭，作为运行回退开关，不暴露新产品页。

快速路径：

1. 查询并校验媒体库根目录的 ID、完整祖先路径及当前账号，取得扫描锚点。
2. 获取目录真实 pickcode：优先使用只读 `/category/get?cid=...` 元数据，严格核对返回身份/祖先链与扫描锚点。无可核对身份或 pickcode 时只认能力不可用，转标准扫描，不复制上游本地换算表。
3. `/files?cid=...&show_dir=0&limit=1150` 分页读子树全部文件，保留父 cid、fid、名称、大小与 pc，按 ID 去重并核对返回根、计数和分页终点。
4. `/app/chrome/downfolders?pickcode=...&per_page=5000` 分页读目录表，核对重复 ID 是否一致，禁止目录环和断裂祖先链。
5. 在内存中解析相对路径，使用与标准扫描相同的名字/路径校验、排除、视频识别与账号规则；过滤完成后形成可信快照。结束时重新检查根锚点及凭据，发现根移动/改名或账号变化时不得采用过时快照。
6. 只有完整快照才投影到 STRM 候选和进度；快照验证前不写本地产物或登记所有权。

目录 ID 超出元数据/端点能力、根为 0 没有 pickcode、端点明确不支持、清单不完整或路径表不可信时，丢弃快速临时数据并最多回退一次标准扫描。不递归调用降级，不拼接两条路径的半成品。账号/授权错误、限流、调用取消或预算耗尽不触发重扫。

本节快速/标准全量路径仅用于确认后的正式任务；预览不得调用整树快速枚举。快照阶段超时不将部分文件称为完整目录；标准扫描阶段继续保留已经读完目录的部分结果。

成功快速扫描的列表请求复杂度为 O(ceil(F/1150)+ceil(D/5000))，另有常数次身份/元数据检查。性能测试只验证请求量与候选一致性，不作真实网盘速度或免限流保证。

## 8. 日志、验证与发布

Service/STRM 负责一次终态与聚合统计；Adapter 只提供受控诊断，不在每层重复 ERROR。沿用 request_id/job_id/library_id/attempt，新增必要的 scan_mode、fallback_reason、attempt_count、wait_ms 和受控错误类型；成功分页保持 DEBUG。不得记录凭据、文件名/路径、pc、产物凭证或临时 URL。

验证矩阵见 implement.md；重点是并发限速、共享冷却、取消、公平性、账号更换、快速/标准等价、抽样预算/标注和产物安全回归。模拟与实盘检查分别报告。不开启新的后台周期扫描，不在测试中进行无界真实网盘遍历。

发布无需迁移。出现非公开端点兼容问题可设置 FAST_SCAN=false 回退标准路径；读间隔可调大。代码回退以 SDK 子任务独立提交为单位，不回退已完成注释或现有用户数据。

## 9. 有限抽样预览

用户选择保留少量目录扫描和文件样例，而不是纯配置预检。确认前不跑全库，确认后完整扫描；两者可能重复读取少量目录，不能称为绝对“只扫描一次”。

用户已确认的上限：最多访问 3 个不同目录、总计最多 5 次上游目录请求、每页最多 200 条、总时间最多 15 秒、返回最多 20 条文件样例。根目录计入目录数，请求上限包含重试；先触及任何一项上限即停止。大根目录可能耗尽请求额度，不能保证每次都会覆盖 3 个目录。该上限不是随机统计意义的代表性样本，不推算全库数量。

使用标准目录分页按层次抽样，遵守现有递归、排除、账号与路径规则，不调用递归扁平文件列表或目录表。首个有效目录响应同时验证授权；不额外调用容量、设备等与预览无关的接口。若保留自动重试，预算必须传到底层并按每次实际发送扣减；预算不足时不再发送。

可以展示已经完整校验的页面中的候选，即使该目录还有后续页，但这些数值仅为抽样已见条目计数，绝不赋予正式扫描完整性含义。完整遍历自然结束且未失败时才可声称 scan_complete；达到目录/请求/时间上限时明确标为抽样未覆盖全部范围。配置和输出检查继续只读。

沿用预览路由及现有 revision、scan_complete、计数、samples、output 字段；OpenAPI 增加必需字段 mode（固定 sample）与 stop_reason（scope_complete、directory_limit、request_limit、time_limit、source_error）。计数说明改为已读取且校验成功的页面内去重结果，不是全库估计值。scan_complete 仅在枚举范围实际耗尽且没有未读/失败目录时为 true；局部无效源文件仍通过 failed_count 报告。前后端类型通过生成器同步，运行时解码验证新增字段，联合发布前后端。

前端显示“抽样发现的视频/候选”，保留源文件/输出路径样例，按停止原因提示结果范围。样本为空显示“本次抽样未发现”，不声称媒体库为空；确认条件仍由资格、账号、当前配置版本和输出可用性决定，不以抽样候选数或采样自然结束为条件。

根目录无法验证、明确授权失效等仍返回相应失败，不能当作空样本成功。超时前连第一页都无法验证时报告超时/上游失败，不放行基于未经验证授权的确认；已验证根目录后可保留有效页面的抽样结果。用户离开页面立即取消请求。任务中心展示确认后的完整扫描进度和最终结果。前端查询关闭自动重试、聚焦/重连刷新和轮询；首次进入、配置 revision 改变或用户明确刷新时才进行有预算的抽样。

抽样上限及最新完整规划均已获用户确认，用户于 2026-11-25 明确批准开始所有任务；本任务在注释子任务验收后实施。

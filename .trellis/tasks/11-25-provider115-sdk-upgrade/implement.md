# 方案 A 执行计划

## 0. 规划及激活前

- [x] 用户已确认抽样预览预算：3 个目录、5 次目录请求、15 秒、20 条样例；响应与前端语义见 design.md 第 9 节。
- [x] 用户于 2026-11-25 明确要求“开始所有任务”，批准最新最终规划。
- [ ] 注释子任务已完成检查/交付，确认当前工作区和任务状态，运行 task.py start 激活本子任务。
- [ ] 加载 prd.md、design.md、implement/check.jsonl 和对应 backend specs，派发 trellis-implement 时首行注明 Active task。
- [ ] 核对固定上游研究与现有 provider 测试注入点，不复制上游代码，不引入完整第三方 driver。

## 1. 底层传输、策略及测试

- [ ] 建立 internal/adapter/provider115，小型可注入客户端、受控端点、操作分类、响应上限和安全错误类型。
- [ ] 实现账号范围共享准入、冷却、公平性和可取消等待；无包级全局状态、无无界 goroutine。
- [ ] 实现最多 3 次只读尝试、总/单次预算、Retry-After 秒值/日期、默认冷却和 context 传播。
- [ ] 模拟测试：不同并发源共享频率、响应完成后间隔、配置调大有效、播放插入分页间隙、后台不饿死、取消释放、长冷却不被缩短、错误文本脱敏、过大/截断响应及无重定向。

## 2. 现有能力接入

- [ ] provider Service 接入账号、目录和播放请求；扫码状态机接入同一传输但不自动重复登录交换。
- [ ] 保留凭据前后比较、账号身份、播放器空 UA、m115 解码和可信播放目标校验。
- [ ] 公开分页限制保持 1–200；内部标准扫描支持 1150 与有依据的 200 回退，保留完整目录提交语义。
- [ ] 更新必要 mocks，禁止用 nil 内嵌接口掩盖新方法未实现；回归旧状态与错误身份，不降低断言强度。

## 3. 快速枚举

- [ ] 实现根身份锚点、目录元数据/真实 pickcode、递归文件页、目录表页与结束时复核。
- [ ] 纯内存路径重建、ID 去重/冲突、目录环/断链、计数变化/缺页和越界检查。
- [ ] 将可信快照接入现有视频/排除/路径规则；非递归库保持标准路径。
- [ ] 快速异常只按白名单回退一次标准；限流/授权/账号变化/取消/预算耗尽不得立即重扫。
- [ ] 模拟等价测试：同一多层树、空库、根目录、非递归、排除、同名源、移动/改名、分页增删、坏名字/pc、缺失祖先；证明请求量按分页而非子目录数增长。

- [ ] 沿用聚合/终态日志，添加必要模式/冷却/重试诊断，日志脱敏回归。
- [ ] 新增/改动文件同步补中文文件职责与主要方法说明。

## 4.1 抽样预览的跨层实现（仅最终批准后执行）

- [ ] 前端解码、抽样计数/停止提示、20 条样例和空样本提示同步；候选为空或抽样未完整不阻止合法确认。

- [ ] 测试大根目录、空库、排除/非递归、三个目录边界、五次请求边界（含重试）、期限、账号变化和只读性。
- [ ] 浏览器验证抽样展示、未发现样例仍可确认、任务导航与完整扫描结果。

## 回滚点

非公开端点不可用先关闭 FAST_SCAN；限流可调大 REQUEST_INTERVAL。行为回滚使用 SDK 独立提交，保持已有注释交付与用户数据。任何未通过检查均不得标记完成。

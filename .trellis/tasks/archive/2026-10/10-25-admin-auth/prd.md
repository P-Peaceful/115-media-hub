# 单管理员登录与管理入口保护

## Goal

为单人、单实例部署提供管理入口保护，打通配置用户名及密码、登录、内存会话、CSRF 校验和前端访问保护，为后续连接及媒体业务提供认证基础。

## Background and confirmed facts

- 用户已批准本任务规划，当前处于实施阶段。
- 用户本轮明确要求管理密码通过 ENV 或 YAML 以明文配置，便于 Docker 部署，取代 `docs/database-design.md` 中“管理密码哈希保存到配置”的旧约定。管理会话仅驻内存，重启清空，不建用户、角色和会话表。
- Notion 功能文档 SYS 02 要求管理访问保护，管理凭据与播放凭据分离；UI 文档第 8.1 节要求登录后返回原页面，会话过期保留非敏感筛选和路由。
- 目前仅有配置加载、健康检查、基础前端路由及同源请求封装；服务端认证、会话和 CSRF 校验均未实现。请求封装已有显式传递 CSRF token 的能力。
- 现有配置优先级为默认值 < YAML < 环境变量；环境变量覆盖项不得由 UI 静默改写。
- 用户进一步要求用户名也可配置，仍然只有一个配置管理员，不引入数据库账户体系。
- 用户确认单个内存会话自创建起固定有效 24 小时；活动请求不延长有效期。会话退出或进程重启时立即失效。
- 用户询问 token + refresh token 方案的复杂度后，确认本任务采用服务端随机会话 ID + HttpOnly Cookie，不引入 access/refresh token 体系。

## Requirements

- R1：以单组管理用户名和密码验证身份，支持环境变量 `MEDIA_HUB_ADMIN_USERNAME` / `MEDIA_HUB_ADMIN_PASSWORD` 或 YAML `admin_username` / `admin_password` 明文配置；每个字段均 ENV 优先，显式空 ENV 不回退到 YAML。用户不需要预先生成哈希，不提供多用户、角色或权限管理。
- R2：提供登录、退出和当前会话查询；会话存内存，自创建起固定有效 24 小时且不因活动请求续期，退出后该会话立即失效，重启后所有旧会话失效。
- R3：服务端保护管理 API，前端保护管理路由；健康检查保持可用于部署探针，播放认证独立设计。
- R4：管理变更请求由服务端校验 CSRF，不能仅依赖隐藏前端按钮或客户端传 token。
- R5：登录页按 Canva UI 设计展示“欢迎回来”、管理员账号和密码输入、部署凭据说明及提交中/可读失败反馈；明确 115 网盘授权在登录后单独配置。用户名或密码错误均返回相同登录失败提示，不暴露哪个字段匹配。登录成功恢复安全的站内目标路由和非敏感查询条件，避免外部跳转。
- R6：会话及密码不进入 URL、浏览器持久化存储和日志；HTTP Cookie 承载会话，前端不持久化认证秘密。
- R7：不提供默认用户名或密码；任一字段缺失、全为空白或配置非法时启动失败，不能开放无认证管理访问。修改 ENV 或 YAML 后重启生效，所有旧会话失效。本任务不提供网页首次设置凭据、修改凭据或配置热更新。
- R8：交付 Docker Compose 环境变量配置示例、YAML 配置示例及用户名和密码修改/重置说明。凭据配置不通过 API 回显；认证逻辑无需将用户名、明文密码或其派生值写入数据库。

## Acceptance Criteria

- [x] AC1（R1/R2/R5）：用户名与密码均正确时可以登录；错误用户名或错误密码均失败且不签发有效会话，失败提示一致；数据库不增加身份或会话表。
- [x] AC2（R2/R3）：未登录、已退出、固定有效期满 24 小时或重启前的旧会话不能访问管理 API；部署健康探针仍可用。
- [x] AC3（R4）：受保护的变更请求缺失或携带无效 CSRF token 时被拒绝；有效会话及 token 可以完成退出。
- [x] AC4（R5）：直接访问管理页引导登录，成功后回到原站内页面；认证状态加载期间不显示受保护内容；会话失效后保留非敏感上下文。
- [x] AC5（R6）：登录、失败、退出及异常日志不含密码、完整 Cookie 或 token；浏览器持久化存储无认证秘密。
- [x] AC6（R1/R7/R8）：分别使用 ENV 和 YAML 的用户名及明文密码可以登录；同时提供时每个字段以 ENV 为准；显式空 ENV 不回退到 YAML，任一凭据字段缺失或全为空白时启动失败。
- [x] AC7（R7/R8）：Docker 部署文档说明如何注入用户名和密码；修改凭据配置并重启后仅新配置有效，旧会话失效，无需手动操作数据库或预先生成哈希。

## Technical Decisions

- 使用服务端内存会话和随机、不透明的会话 ID，通过 HttpOnly Cookie 传输；不使用 JWT、access token 或 refresh token。
- 会话创建后 24 小时绝对过期，不采用滑动续期；超时后服务端拒绝该会话并清理记录。
- 当前会话接口返回短期 CSRF token，前端只放内存；受保护的变更请求和退出请求必须由服务端验证。
- 登录失败对用户名错误、密码错误和缺失凭据使用相同状态码及提示；凭据比较采用常量时间比较。
- Cookie Secure 由可选布尔配置 `cookie_secure` / `MEDIA_HUB_COOKIE_SECURE` 显式控制，默认 false 以兼容当前 HTTP 回环部署；通过 HTTPS 提供服务时部署者必须启用。应用不根据转发头猜测 TLS。
- 登录后仅接受以单个 `/` 开头且不以 `//` 开头的站内相对路径；拒绝绝对 URL、协议相对 URL和反斜杠混淆路径。只恢复非敏感查询参数。
- 登录页遵循 Canva 设计中的“欢迎回来”管理登录界面；管理登录与 115 网盘授权分开，后者在登录后配置。
- 认证配置在启动时验证：ENV 字段存在时覆盖 YAML（空值仍视为显式覆盖并导致验证失败）；用户名和密码分别 trim 后不得为空，原始密码值用于验证，不 trim 密码内容。

# 前后端独立项目初始化

## 目标
建立可运行、可独立管理的前后端项目根目录，提供可复现的开发和构建命令，为后续业务开发做好基础准备。

## 背景
仓库已有开发工具和确定的技术架构，但尚无应用代码。用户明确要求前后端根目录分开。现有目录规范使用 web/ 和仓库根目录下的 Go 模块；本任务调整这些路径，保留已确定的技术栈。

## 需求
- R1：Vite/React/TypeScript 应用、包清单和 pnpm 锁文件放在 frontend/；Go 模块、入口、内部包和迁移文件放在 backend/。
- R2：遵循已确定的 React 19+、HeroUI v3、Tailwind v4、React Router、TanStack Query，以及 Go/Gin/GORM/SQLite/goose 架构。只引入初始化实际使用的依赖；Zustand、调度和工作池等按后续需求引入。
- R3：提供满足基本无障碍要求的初始页面，通过开发代理展示后端健康状态，包含加载、成功和失败状态。
- R4：提供配置示例、结构化启动和请求日志、优雅关闭、SQLite 配置、首个版本化迁移，以及最小存活检查和就绪检查端点。
- R5：通过统一的 OpenAPI 定义健康检查契约，生成 Go 和 TypeScript 传输类型，并提供可重复执行的生成命令。
- R6：提供前端资源嵌入、开发说明、可复现的构建和容器配置，以及适用的本地与 CI 质量检查；固定工具版本。
- R7：同步项目规范，反映新的根目录和实际实现。
- R8：本任务的规划文件和说明使用中文；命令、路径、标识符和技术名称保留原文。

## 验收标准
- AC1（R1、R2）：frontend/ 和 backend/ 可从各自根目录安装依赖并构建；提交一份前端锁文件和后端 go.mod/go.sum。
- AC2（R3、R4）：两个开发进程均可启动；前端通过代理展示健康状态；就绪检查反映数据库可用性，存活检查保持最小化。
- AC3（R4）：首次启动可创建 SQLite 数据库并应用初始迁移；重复启动成功；启动错误可定位，关闭时释放资源。
- AC4（R5）：契约重复生成结果一致，生成代码可编译。
- AC5（R6）：在环境支持的情况下，格式、lint、类型、有效行为测试、竞态测试和生产构建全部通过；浏览器冒烟测试覆盖初始页面。明确记录环境限制。
- AC6（R6）：生产二进制可提供前端 SPA 和健康检查；未知 API 和静态资源路径不会返回 SPA。尝试容器构建和冒烟验证并记录结果。
- AC7（R7）：README 和规范准确描述实际目录、命令、选定工具的精确版本及初始化范围。
- AC8（R8）：需求、设计、实施计划及上下文清单说明使用中文。

## 范围外
身份认证、115 接入、媒体浏览与媒体墙、媒体库、同步、STRM、播放、元数据、持久化任务、cron 调度和 SSE 行为。不添加生产凭据或仅用于占位的空业务包。

## 延后事项
实施时解析、固定并验证兼容的依赖和生成器版本。已有 V1 业务需求仍由后续任务实现。

# 管理员认证方案

## 状态与范围

用户已于 2026-11-07 批准最终规划；之后将默认输出目录先更新为 `/media`，最新要求为 `/app/media`。Docker 部署中外部卷的容器目标均位于 `/app/` 下；本地开发的数据库继续位于项目 `backend/data/`。实现已获授权。数据库结构、API、服务、CLI、界面和集成验证共同构成认证边界，因此由同一个集成任务统一负责。

保留模块化单体结构：`internal/app` 负责组装依赖；`internal/service/auth` 负责认证策略和仓储接口；需要时由 `internal/domain/auth` 保存业务类型与不变量；`internal/repository/sqlite` 负责存储实现；`internal/http` 负责传输层和 Cookie。React 功能代码放在 `frontend/src/features/auth`，路由组合由 `app` 负责。

## 存储与事务

新增带版本号的迁移；不得修改 `00001_application.sql`，也不得调用 AutoMigrate。在 SQLite 仓储边界内保留已配置的 GORM 句柄及其现有底层连接池。

- `administrators`：通过约束保证单例，使用不透明 ID、唯一用户名、密码哈希和时间戳。
- `system_settings`：通过约束保证单例，保存服务 URL、绝对输出路径、会话有效天数和时间戳。
- `admin_sessions`：保存随机高熵会话令牌的唯一哈希、管理员外键、CSRF 绑定和固定过期时间。不得保存原始 Cookie 令牌。为过期时间和访问查询建立索引；以有界工作量按需清理过期会话。
- `audit_records`：保存已知时的操作者标识、操作、目标标识、时间、结果以及请求/操作关联信息。不得保存提交的密码、密码哈希、Cookie 值或 CSRF 密钥。

初始化在一个短事务中写入单例管理员、设置、首个会话和成功审计记录。由数据库约束处理并发请求，并将失败的一方映射为 409。密码哈希计算和文件系统检查必须在事务之外执行。初始化只保存经过验证的服务器路径，不创建媒体文件或媒体库。

登录先加载管理员并比较 bcrypt 哈希，再在事务中原子地创建会话和成功审计记录，同时核对预期凭据哈希。这样，如果密码重置在密码比较完成后、会话写入前提交，旧密码仍无法创建会话。直接使用锁定版本的 `golang.org/x/crypto/bcrypt` 依赖，并选择经过验证、登录延迟合理的生产成本（初始目标为 12）。密码必须为 8–32 个可打印的非空格 ASCII 字符，即 U+0021–U+007E；不得裁剪密码。拒绝非 ASCII 字符、空格和控制字符；不强制字符类别组合。用户名为 3–32 个 ASCII 字母、数字、下划线、句点或连字符，区分大小写。在浏览器中确认两次密码；API 只接收实际密码，不接收确认值。

登出在同一事务中删除会话并写入审计。密码恢复在同一事务中更新密码、删除所有会话并写入成功审计。若必须写入的成功审计记录失败，则回滚变更并返回操作错误，不能返回误导性的成功结果。登录失败时若审计写入失败，应返回安全的服务不可用结果并记录已脱敏的审计故障；不得创建会话。匿名请求限流必须有界，不能因此造成无界的数据库审计增长。

## HTTP 契约

先扩展 `api/openapi.yaml`，再实现调用方，并重新生成传输层代码。

| 路由                           | 行为                                                                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/v1/auth/bootstrap`   | 返回最少量的初始化/认证状态、相关过期时间；仅已认证时返回管理员信息，并返回 CSRF 令牌。匿名响应不得包含密钥或设置。必要时建立匿名预认证 Cookie。 |
| `POST /api/v1/auth/initialize` | 接收用户名、密码、服务 URL、输出目录和有效期；只允许初始化一次，返回会话 DTO 并设置已认证 Cookie。                                               |
| `POST /api/v1/auth/login`      | 接收用户名、密码和记住登录选项；返回会话 DTO 并设置 Cookie。                                                                                     |
| `POST /api/v1/auth/logout`     | 验证会话和 CSRF，撤销会话、使 Cookie 过期，并返回 204。                                                                                          |

明确各端点必需字段、可选/可空语义、请求体大小限制，以及输入错误、凭据错误、未初始化/已初始化、CSRF、过期和限流对应的稳定错误。按需保留 400/401/403/409/429/500/503 状态码和请求 ID 错误封装；限流时返回 `Retry-After`。凭据相关响应必须设置 `Cache-Control: no-store`。

认证中间件默认保护未来的 `/api/v1` 管理端点，只显式放行 bootstrap、登录、初始化和公开健康检查。不要让未来的处理器依赖开发者逐个记得添加认证。此任务不添加 SSE、播放或上游服务提供方代码。

## 会话、CSRF 与部署

从 32 个明确生成的 `crypto/rand` 随机字节生成会话令牌，并编码为 64 位十六进制字符；由此派生不可逆的查询哈希。不得假设 `rand.Text` 永远返回固定长度。Cookie 使用 HttpOnly、Path=/ 和 SameSite=Lax。浏览器不得通过 JSON 请求体、URL 或 local/session storage 接收会话密钥。

Bootstrap 返回仅保存在内存中的 CSRF 令牌，并将其绑定到短期预认证 Cookie 或已认证会话。重新获取 bootstrap 时应复用仍有效的预认证绑定，避免不必要地轮换。匿名 bootstrap 绑定可在重启后轮换；已认证会话应通过重新获取 bootstrap 继续工作。初始化或登录成功时轮换已认证会话和 CSRF 绑定，包括替换已有会话的情况。所有会改变状态的认证/管理请求都必须携带 `X-CSRF-Token`，并以常量时间比较验证绑定。令牌验证还要结合同源请求检查；没有 Origin 的 CLI 请求仍须提供有效 CSRF 绑定。不得信任攻击者可控的转发请求头来判断安全性。

使用启动配置 `MEDIAHUB_COOKIE_SECURE` 支持 HTTPS 反向代理部署；适用时也根据直连 TLS 请求启用 Secure Cookie。文档说明外部 HTTPS 在代理处终止时如何启用该设置。保留开发环境中的同源 Vite 代理和不信任代理的默认行为；由于锁定版本的 Vite 字符串简写会重写 Host 并与严格 Origin 检查冲突，必须使用显式代理对象并设置 `changeOrigin: false`。

数据库中的会话有效期固定为 1/7/30 天，默认 7 天。记住登录时，将 Cookie 的 Max-Age/Expires 设置为剩余有效期；否则不设置这些持久化属性。两种 Cookie 都受服务端过期时间约束。浏览器恢复会话的行为由浏览器控制，不得将其描述为绝对登出保证。不提供按闲置时间滑动续期的承诺。

对昂贵的认证/初始化请求使用有界、并发安全的限流器，按可信的对端信息进行限流，并设置全局准入上限和过期/淘汰机制。不得引入 Redis、信任任意 `X-Forwarded-For` 值，或保留长期无界的按输入状态。使用可控时钟测试拒绝和恢复行为。

## 设置校验

服务 URL 必须是完整的 HTTP(S) 源，并从当前浏览器源预填。拒绝 userinfo、查询参数、片段和非根路径，因为当前版本的路由/构建不支持将应用挂载到路径前缀下。保存的服务 URL 是配置信息，不是重定向目标或可信代理来源。

输出路径必须是经过规范化的服务器绝对路径，必填，默认 `/app/media`，并由用户明确选择。此值取代本任务早先确定的默认路径；实现期间同步更新相关部署文档/规范。Docker 镜像内的数据卷目标统一置于 `/app` 下，包括 `/app/data`、`/app/logs`、`/app/cache`、`/app/backups` 和 `/app/storage/quarantine`；本地开发仍使用项目内 `backend/data/` 数据库。拒绝格式错误或相对路径，并说明这是服务器上的路径。不得实现浏览器/服务器文件夹选择器、自动更改宿主机路径，或仅凭语法校验就承诺目录可写。README 说明后续媒体操作所需的输出挂载和目录所有权。

## 密码恢复 CLI

提供 `mediahub admin reset-password` 命令。命令通过正常的迁移/仓储边界打开已配置且已存在的数据库；TTY 模式下隐藏输入并二次确认密码，或通过显式指定的 `--password-stdin` 接收脚本/容器输入。不得将密码作为命令参数或秘密环境变量接受；输入模式不可用时，返回清楚的操作指引。恢复流程不得创建管理员。

文档说明如何停止应用执行本地维护，包括挂载同一持久卷的容器调用方式，以及成功后的重启步骤。不得增加公开 HTTP 重置端点，也不得使用硬编码恢复密码。恢复日志和审计记录应标记本地维护操作者及操作，但不得包含密码等秘密值。

## 前端组合与数据归属

路由包括 `/setup`、`/login`、受保护的 `/` 和现有的未找到页面。通过 TanStack Query 获取 bootstrap，并根据生成的 DTO 进行运行时校验；不得持久化认证布尔值。认证边界负责加载、离线/重试、需要初始化、未认证和已认证状态，并避免页面闪烁。

所有适用的前端组件优先使用 HeroUI 3.2.7 文档化组件，包括表单、输入框/输入组、按钮、复选框、选择器、卡片、对话框、链接和状态反馈。保持组件库对可访问性和交互行为的控制；布局/内容可使用语义化 HTML/CSS。每个选用 API 都要查阅当前官方 v3 文档；不得使用 v2 写法或已弃用属性。使用 HeroUI 的 `useTheme("system")` 支持系统偏好、持久化的手动亮/暗主题选择和根节点主题属性。HeroUI 组件配色使用 HeroUI 语义主题变量。使用 Lucide 图标、统一的紫色语义色和本地媒体文件夹插画，并确保插画符合参考设计；不得接受粗糙图标替代作为最终效果。实现前核对组件文档。将参考图中的两页分别实现为独立路由，不得把两个画板放在同一页面。保留主要内容区品牌标识，移除完整顶部栏和 115 卡片。独立主题切换按钮放在右下角。遵循减少动态效果的系统偏好设置。

表单草稿值保存在本地组件状态中。CSRF 只保存在内存中，并按需重新获取 bootstrap；使用同源凭据提交，不自动重放变更请求。前后端字段约束保持一致，并在有帮助时展示安全的后端消息/请求 ID。不得将密码传入路由状态、查询键或分析系统。

受保护 API 返回 401 时，先清除/取消受保护查询，再带着经过验证的本地返回地址跳转至登录页。登出/过期后阻止旧请求重新填充受保护缓存。页面仍打开时应能感知会话过期，使用有界过期定时器和窗口重新聚焦刷新，而非持续轮询。登录和初始化后重置认证边界。

现有健康页面作为受保护的临时首页，并提供登出功能；健康检查 HTTP 端点继续公开。忘记密码入口展示无障碍说明，其中包含实际 CLI 命令和部署文档链接。此任务不增加邮件配置、设置编辑器或仪表盘。

## 兼容性、迁移与回滚

现有数据库从仅有应用表结构升级到新结构时，不应包含管理员，因此进入首次初始化流程。健康检查客户端继续使用原端点。现有浏览器健康检查测试应适配受保护路由，同时独立保留健康 API 断言。

当前集成测试会让桌面/移动端项目并行访问同一个真实数据库；应为其隔离数据库/服务实例，或明确串行执行会改变状态的真实后端认证场景。不要让多个浏览器项目意外竞争初始化同一个共享数据库；应在仓储/HTTP 边界单独保留有意设计的并发测试。

部署迁移前，使用 SQLite 一致性备份。管理员账户真实创建后，回滚应使用匹配版本的二进制和备份；不得把删除凭据/设置/审计表宣传为保留数据的降级方案。新迁移必须明确说明/拒绝不可逆的 Down 操作，或测试受支持的安全回退方式。

## API 时效性与可读性约定

用户的 API 规范同时适用于前后端：所有新增/变更的依赖 API 和标准库调用都必须使用锁定版本支持且未弃用的 API。适用时检查官方文档/发布说明以及已安装类型/源码中的弃用标记；仅编译通过不足以证明 API 仍受支持。将重要 API 选择或替代记录在实现验证文档中。避免无必要地升级依赖。

HTTP DTO 绑定/Cookie 处理必须与认证策略和 SQL 分离。前端 API 解码、查询/变更编排和界面展示各自有明确归属。按内聚职责划分模块，保持可读的边界；不机械拆出每个短函数，也不增加通用框架。检查人员必须同时审查代码清晰度和组件/API 选择。

视觉检查应将每个实际路由与对应画板比较，并排除已移除的顶栏/授权元素。检查桌面比例、字体、输入框/按钮尺寸、插画、渐变、阴影和间距，然后检查移动布局及暗色主题。保存并检查截图，修复明显偏差；功能测试通过不能替代视觉还原检查。

## 验证职责

服务测试负责登录/初始化/会话/恢复策略、时钟、限流、操作日志字段和审计失败行为。真实 SQLite 测试负责唯一性、事务回滚、迁移升级、撤销和重启持久性。HTTP 测试负责认证/CSRF/Cookie/状态码/请求体限制/受保护路由。前端测试负责渲染、校验、异步错误、重定向和缓存清理。Playwright 负责键盘/密码显示/恢复指引、响应式亮暗主题布局，以及完整的真实“初始化 → 登出 → 错误/正确登录 → 登出”流程。生产环境 smoke test 负责验证嵌入式资源和公开命名空间没有回归。

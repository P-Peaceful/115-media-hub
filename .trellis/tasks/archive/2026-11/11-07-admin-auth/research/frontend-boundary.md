# 前端实现边界

初始项目公开展示健康页面，没有认证，也没有初始化/登录状态。最小完整改动是新增认证功能，负责生成契约解码、内存 CSRF、查询/会话迁移、表单校验与展示；应用路由组合认证边界和受保护的健康首页。

预期文件：`src/features/auth/*` 存放上述职责及行为测试；`src/assets/media-folder.svg` 保存调整版参考插画；`app/app.tsx` 负责路由组合和缓存归属；共享 API 错误/client 负责安全错误封装及未授权通知；样式负责统一紫色 token 和响应式认证布局；健康页接收注入的登出操作；E2E 覆盖模拟流程和一个串行真实后端工作流。生成 schema 归后端负责；主代理负责根目录测试架构/文档/规范。

不包含：服务提供商授权、顶部状态栏/界面、仪表盘、文件系统选择器、持久化认证状态、账户/设置编辑。既有公开健康 API 行为和健康组件测试保持不变。不需要无关重构。React/HeroUI 布局元素可使用语义化 HTML/CSS；标准交互仍由 HeroUI 提供。

后端实现者确认的契约：bootstrap/initialize/login/logout 端点及生成类型 AuthBootstrap/AuthSession/InitializeRequest/LoginRequest；状态变更请求通过同源 Cookie 和 `X-CSRF-Token`。真实后端测试为各浏览器项目提供独立全新数据库；所有变更均放在每个项目的单一工作流测试内。

## 密码策略后续

用户现要求密码为 8–32 个可打印非空格 ASCII 字符。最小改动是认证功能校验器及简明字段提示，并应用于登录、初始化和确认密码。按主代理澄清，保留原始输入，由 HeroUI 校验拒绝超长提交。不得添加原生 maxLength、切片或粘贴处理器，以免改动密钥内容。测试覆盖长度边界、禁止的 Unicode/空格/控制字符（包括末尾 LF/CR）、粘贴原值保留和阻止提交。API 解码、会话行为、视觉组合、数据库/进程状态均不属于此次后续改动。后端负责重新生成 schema；主代理负责文档/集成组装。

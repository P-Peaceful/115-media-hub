# 技术设计

## 边界与数据流

设置页面沿用受保护应用外壳和认证状态，分为管理员安全及 115 账号。先定义 OpenAPI 管理端点和生成类型；服务端认证、CSRF、输入验证、错误映射沿用现有约定。管理员资料和会话设置交由认证服务及 SQLite 仓储处理；敏感变更和必要审计在事务内完成。修改凭据验证当前密码，保留当前会话并撤销其他会话，处理并发旧密码登录与资料变更，避免撤销后签发旧凭据会话。会话期限只影响新建会话。

115 适配器由本项目实现，封装固定上游地址、超时和响应解析；服务端维护有界、短期、绑定管理员会话的扫码状态，避免并发重复兑换或过期轮询覆盖新授权。前端获取二维码和非敏感状态，服务端兑换并持久化凭据；取消、过期、删除及主动退出时清理临时状态；其他会话被撤销后最多保留至二维码两分钟到期，兑换时重新验证会话，不能保存授权。扫码失败不破坏既有授权。用户明确选择直接接受不同账号，无身份比较或换号确认。

Cookie 账号资料通过 `my.115.com/?ct=ajax&ac=nav` 读取头像、会员状态、会员过期时间和永久会员标记；参考实现将 `vip` 的 0 映射为非会员、1/2 映射为会员，其他/缺失值保持未知，不暴露原始等级。`webapi.115.com/files/index_info` 提供容量及 `login_devices_info.list` 登录设备。主动检查授权通过强制刷新 `nav` 实现：明确成功为有效、明确要求登录为失效、网络或其它响应错误为无法确认。

总览 115 连接卡、容量卡及侧栏授权卡以 `dashboard-reference.png` 为视觉验收参考，仅替换这些卡片的内容和样式，不复制全局导航/面包屑。账号状态与容量百分比从实时 API 数据派生，检测时间用查询成功时间。Cookie 授权没有稳定的固定到期时间，因此连接卡展示检查状态与最近检测时间，不展示推算的剩余授权天数；会员到期字段只表达会员权益期限。

总览中的系统状态与 115 连接状态使用同规格的 HeroUI 状态徽标和一致的说明区高度，使两卡下方详情行在桌面和窄桌面宽度下对齐；说明文案允许换行时，状态区需预留相同空间。

桌面侧栏的设置入口与 115 授权卡之间留出 12px 间距；在授权卡展示的最矮桌面断点仍保持菜单无滚动和卡片可见。

## 存储和部署

SQLite 添加单账号凭据记录，按用户决定直接保存 115 凭据，不增加加密或主密钥配置。这是对项目基线外部凭据加密要求的明确例外；数据库及其备份包含可直接使用的凭据。数据库迁移、授权替换和删除保持一致性；脱敏日志与审计不包含凭据、二维码临时秘密或原始上游响应。现有未配置 115 的部署可平滑升级。

## 验证与风险

注入 HTTP 客户端和时钟以模拟扫码全流程、超时、上游异常、并发及授权持久化；验证认证事务、审计失败回滚、CSRF 与会话撤销。真实扫码需要可访问 115 的网络及用户操作，若无法执行须明确报告。上游协议、设备类型和 User-Agent 可能变化；在实现时以研究资料为起点核实，不承诺第三方接口稳定。数据库及备份需按包含凭据的数据处理；失败不得覆盖已有授权。

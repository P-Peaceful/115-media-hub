# 实施计划

1. 阅读前后端相关规范，研究并验证 115 的 Cookie 目录列表、路径、分页、搜索、排序及类型筛选；记录请求/响应与限制，确认能覆盖完整目录语义。
2. 定义 OpenAPI 契约和错误状态，生成客户端/服务端类型；实现后端只读浏览服务，复用账号凭据并处理替换竞态、取消、超时及脱敏。
3. 实现受保护页面、导航、目录交互、列表/网格、详情侧栏、复制和各异步状态；媒体库占位按 PRD 处理。
4. 使用模拟上游和前端测试覆盖多级目录、大目录分页、过滤排序、账号变化、授权与故障、路径复制；进行桌面布局、键盘及主题检查。
5. 运行适用的 `make check`、`make test-e2e` 及构建检查；条件允许时用实际 115 账号联调，分别报告真实联调与模拟测试结果。

开始实现前需完成规划评审和显式批准；用户已同意搜索无法可靠实现时暂缓；其他已约定行为不得静默退化。风险点为外部接口变化、分页期间目录变化和账号替换竞态；回滚不涉及已有账户数据。

## 变更边界

现有导航尚无网盘浏览，后端尚无目录读取能力。变更限于 115 只读目录访问、OpenAPI 契约与生成类型、受保护路由和浏览界面及必要验证；不实现媒体库或网盘写入，不改动账号授权逻辑的既有行为。

## 验证记录

- Node 24.13.0 下 `make check` 通过，包含 93 项前端测试、Go 测试与 race、lint、生成契约一致性和前端构建。
- 系统 Chrome 下以模拟数据检查了桌面、深色窄屏和详情展开；真实账号经 Go 服务成功读取根目录并分页，抽样了排序参数和视频类型筛选。
- 完整现有 E2E 套件未通过：单 worker 为 6 通过、11 失败、3 跳过。独立 HEAD 基线复现账号信息及健康状态中的三个失败；其他登录与侧栏失败尚未全部归因。大目录及其他文件类型尚未做真实账号验证。

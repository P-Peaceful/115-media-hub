# 技术设计：媒体库管理与配置

## 边界

本期是端到端媒体库配置管理，不启动扫描任务、不操作媒体文件。复用认证和 115 只读目录浏览；新增媒体库领域、持久化、管理 API 及前端页面。启用状态仅表示配置可在未来参与处理，不能推断运行状态。

## 数据与接口

- 在 SQLite 中通过新迁移存储媒体库身份、名称、描述、115 目录 ID 和展示路径、媒体类型、启用状态、输出及文件规则等配置；持久化路径映射和其余结构化配置，保证读写往返。115 ID 始终为字符串，路径展示信息不替代目录 ID。
- 在 `api/openapi.yaml` 先定义列表、详情、创建、更新、启用状态和删除的契约与字段校验，然后生成 Go/TypeScript 类型。沿用会话鉴权、CSRF、错误格式与分页约定；服务端对所有输入重新校验，删除只影响配置数据。
- 目录选择通过现有云盘列表 API，处理分页和授权/网络错误；不把 Cookie 传给前端。目录及账号后续变化时不得把历史展示路径当作目录有效性的证明。
- 对设计图中的规则选择提供能保存的明确字段和选项；未具备运行语义的字段只作为配置持久化，不声称已经生效。模型要可扩展并避免与未来执行记录或文件归属表混淆。

## 前端

在现有受保护路由与应用外壳中增加媒体库首页、新建和详情/编辑视图。通过 TanStack Query 管理请求与缓存失效；列表两列布局在窄视口折为单列。复用现有目录浏览和错误展示模式，保存、启停、删除后刷新相关数据。不存在真实运行数据的统计使用明确的不可用/暂无数据状态，相关执行按钮禁用并说明原因。

## 兼容与风险

迁移应保留现有数据库与设置，应用现有迁移约定；不得删除或覆盖媒体文件。后续实现同步时须重新定义执行状态、扫描完整性、文件归属与冲突等契约，而不是把本期启用状态当成执行状态。遵循现有日志脱敏与敏感操作审计规范。115 上游不可用时，已有配置仍可查看；选择新目录时展示相应错误。

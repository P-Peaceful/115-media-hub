# 技术设计：重构媒体库配置

## 边界

本任务更新媒体库创建/编辑配置表单与持久化契约。扫描、监听、刮削、播放链接生成及媒体文件操作仍不实现。新增配置项仅表示未来执行所需的持久化偏好。

## 表单结构

在 `frontend/src/features/media-library/library-page.tsx` 将表单分为四张卡片，与参考图一致：

1. **基本信息**：名称、媒体类型、语言偏好（仅简体中文）、刮削源（TMDB/MetaTube/不刮削，默认 TMDB）。
2. **目录绑定**：媒体库网盘目录、排除目录、包含子目录、跟随网盘目录变更。排除目录可手动输入路径，也可复用目录选择器。
3. **输出设置**：本地输出目录、STRM、NFO、海报与封面三个生成选项、文件编码。海报与封面合用一个开关（`generate_poster_cover`）。移除目录结构选项。
4. **STRM 链接配置**：链接类型、直连域名、链接格式 Tab。移除链接有效期、链接参数和多清晰度开关。

整个文件规则卡片和自动清理能力均不提供。不在表单显示描述、路径映射、目录结构、文件规则或启用状态；启用状态继续由现有独立启停接口管理。表单顶部按参考图展示文件夹图标、标题、说明和取消/保存操作；卡片按“基本信息、目录绑定、输出设置、STRM 链接配置”顺序排列。桌面卡片为两列，较窄视口单列；桌面卡片内字段使用左侧标签、右侧控件的横向行布局，较窄视口改为纵向布局。输出目录为服务器本地绝对路径，使用可编辑输入框；浏览器无法选择服务器路径，因此输入框末尾的文件夹图标仅作视觉提示，不表现为可点击的伪选择器。保留现有网盘目录选择器、字段错误和 pending/error 状态。布局沿用 HeroUI v3 与 Tailwind。

## 配置契约与默认值

### 2026-11-19 新增 STRM 冲突策略与格式示例

- OpenAPI LibraryConfig/Library 新增必需枚举 `strm_existing_file_policy: skip | overwrite`，新建默认 `skip`；Go Config、严格 HTTP allowlist、前端 decoder、编辑草稿及生成类型保持同步。JSON 持久化无需数据库迁移，延续本任务不兼容旧配置的约定。
- 输出设置中生成内容下方提供“STRM 已存在时”选择，标签为跳过/覆盖。关闭 generate_strm 时禁用但保留选择；API 仍保存合法策略，实际执行仍未实现。
- 链接格式行保持与其他字段一致的标签宽度，消除空 Tabs.Panel 对垂直居中的影响，示例在选项下方对齐控件列；需要时面板承载各自示例，不保留无意义的空面板间距。
- 格式示例为纯展示文本，不是可播放链接：固定 HTTPS 与示例文件名/ID，域名为空使用 media.example.com，输入有效域名后实时替换；对无效域名输入不构造可点击链接。保留 IPv6 与端口的显示；随格式/域名变化，不为 direct/proxy 发明不同 URL 路径。

在 `api/openapi.yaml` 扩展 LibraryConfig/Library：语言偏好、刮削源、排除目录路径、包含子目录、跟随网盘目录变更、海报封面开关、文件编码、STRM 直连域名及 STRM 链接格式。现有 `generate_strm`、`generate_nfo` 字段继续使用；移除 `link_expiry` 及不再展示的旧表单配置字段。刮削源使用新枚举字段。

链接类型沿用 `direct | proxy` 的稳定 API 值，前端显示为“直连”和“302 代理”，新建默认值改为 `proxy`。格式使用明确的有限枚举（原名/文件 ID）；域名为空时表示不配置自定义直连域名。语言、来源和编码采用有限枚举以便校验。语言本期仅支持 `zh-CN`；刮削源枚举为 `tmdb | metatube | none`，默认 `tmdb`；UI 文案分别为 TMDB、MetaTube、不刮削。目录绑定的排除目录为可选路径；两项目录行为开关采用布尔值。

配置存于 JSON，不需要新增 SQLite 列。服务端验证需对新枚举、域名长度/格式、路径长度和布尔字段做约束。新增的执行偏好目前不驱动副作用。

## 数据迁移与兼容性

- 不实现旧 JSON 字段映射、默认值回填或配置迁移。升级前保存的媒体库配置不保证能在新版本读取；必要时用户需重新创建配置。
- 针对新增策略导致已有列表整体失败的回归，允许一个明确例外：持久化读取时仅在 JSON 缺少 `strm_existing_file_policy` 键时补 `skip`，不写回、不更改 revision，不掩盖显式空值/null/非法值；HTTP 创建/更新仍保持必填校验。本地运行中实例如需立即恢复，可在备份后仅为缺失字段的记录补默认值并递增 revision，避免中断用户调试进程。
- 移除旧的表单配置字段后，同步调整媒体库详情中对已移除字段的展示，保证详情视图继续符合新响应类型。
- API/OpenAPI 对新配置字段保持严格 required/enum 验证。启用状态继续使用现有独立接口。
- 新配置仍只描述偏好，不触发本地/网盘文件操作。

## 验证与回滚

### 删除确认交互优化

- 仅调整媒体库列表删除确认的前端展示与交互：使用当前安装版本 HeroUI AlertDialog 及内置复合结构，沿用现有鉴权、CSRF、删除请求和列表失效逻辑。
- 采用危险语义图标、清晰标题、可换行名称与配置删除说明，底部排列取消/危险确认操作，使用现有主题与组件默认样式。
- 在提交期间禁用重复提交与关闭；失败保留弹窗并可重试，打开下一次确认前清理旧操作错误。组件负责焦点管理，默认聚焦取消按钮。
- 更新单元角色断言为 alertdialog，检查取消/失败重试/提交保护；浏览器只操作 mock 数据，检查桌面与窄屏暗色截图及键盘行为。

- 更新 OpenAPI 后运行项目生成命令更新 Go 与 TypeScript 生成类型，并执行 generated drift 检查。
- 覆盖默认值、字段验证、新配置往返、链接格式切换和移除项不显示。
- 回滚时还原前后端/API 配置代码即可；本次不改 SQLite 表结构，不需数据库迁移；旧版配置数据不做兼容处理。

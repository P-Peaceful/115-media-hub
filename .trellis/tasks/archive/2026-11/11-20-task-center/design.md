# 任务中心设计

## 模块边界

在现有 Go 单体中加入任务与计划服务。服务负责验证提交、查询和状态迁移。进程内 worker 负责领取任务、调用模块和记录执行结果。调度器负责根据计划创建任务。由 `internal/app` 在启动时显式注入模块执行入口，管理组件启停。各模块继续拥有自己的扫描、文件写入、清理、上传及其他业务规则。

| 设计分类 | 当前能力 | 接入条件 |
| --- | --- | --- |
| 扫描 | 115 分页目录浏览 | 扫描模块提供媒体库级扫描及可核验的目录完整性结果 |
| STRM 生成 | 媒体库保存生成配置 | STRM 模块提供生成入口和文件处理结果 |
| 同步 | 全量、增量和执行预览使用前端演示 | 同步模块提供实际同步入口 |
| 检查 | 基础服务健康检查 | 媒体检查模块提供媒体库级检查入口 |
| 清理 | 已有自动清理规范 | 清理模块提供候选筛选、自动清理和结果记录 |
| 刮削 | 媒体库保存刮削源等设置 | 刮削模块提供业务执行入口 |
| 回传 | 115 账号和目录读取 | 回传模块提供带冲突检查及结果核验的上传入口 |

生产注册表初始为空。用测试注入验证有能力时的完整链路，生产能力接口据注册表返回七类可用性和不可用原因。模块接入时声明是否支持暂停、恢复、中断后核验和按失败项重试。任务详情和计划编辑据此提供交互。已保存任务的处理器缺失时保留历史，返回明确的不可用原因。调度器跳过暂不可用的计划并记录原因。

模块入口接收任务标识、媒体库标识及任务生命周期上下文，通过回调提供进度、任务项和安全日志。执行前由模块从媒体库服务读取对应配置。按失败项重试由服务根据父任务的失败记录生成内部项标识，客户端请求只提交重试范围。切换配置后再次运行时读取执行开始时的已保存配置，运行内使用同一配置版本。没有复用条件的能力在业务模块开发完成后再注册。

## 状态和存储

- SQLite 记录计划、任务、任务项和可查询的任务日志。保留任务来源、父任务、计划发生时间、媒体库标识、时间戳和终态。
- 任务包括排队中、运行中、已暂停、已完成、失败、已取消。部分失败作为完成结果记录，保留成功、失败、跳过统计。排队取消即刻生效，运行取消由模块通过上下文感知，等待模块退出后落终态。仅对支持检查点的模块开放运行暂停及恢复。
- 条件更新保证单次领取。按媒体库协调互斥写任务，模块仍负责其业务资源锁和外部副作用的幂等。文件和网络操作在数据库事务外执行。
- 启停、编辑和删除影响未来触发，已提交运行继续由任务中心管理。到期计划的任务写入和下次运行时间更新使用同一事务。按计划、计划时间和库标识去重。全部媒体库计划在触发时解析已启用且支持该类型的目标库，每库各有运行记录。
- 重启后恢复已排队任务。曾在运行的任务先由模块核验副作用和检查点，可恢复时继续，否则以可诊断的中断结果结束。保留历史和父子重试关系。
- 按基线采用 `robfig/cron/v3` 计算周期。设计默认使用 `Asia/Shanghai` 调度，计划保存 IANA 时区，执行时点以 UTC 持久化。自定义周期使用五字段 Cron；每月缺少指定日期时跳过该月。服务恢复后跳过停机期间错过的计划发生时间，继续计算下一次触发。

## 接口和界面

先更新根目录 OpenAPI，再生成 Go 和 TypeScript 契约。管理接口沿用管理员会话、CSRF、分页及错误格式。资源覆盖任务类型能力、任务列表与详情、失败项、关联日志、单条任务操作、计划列表与编辑。手动提交使用任务类型和媒体库标识，异步提交返回持久化任务引用。未注册类型在提交或保存时返回稳定的业务错误。

沿用 React Router、HeroUI 和 TanStack Query。通过 SSE 通知状态和进度变化，重连后重新查询持久数据。为任务列表与计划列表提供真实空状态，详情展示模块实际报告的数据。通知偏好保存在计划中，设计采用站内任务完成提示，覆盖成功、失败、部分失败。外部消息渠道另行规划。

## 部署和回退

沿用单实例和现有数据库。迁移采用新增表，验证旧库升级及已有数据保留。回退前停止调度并等待 worker 退出，保留数据库以便后续继续查询任务历史。业务模块仍按自身契约记录和核验外部副作用。

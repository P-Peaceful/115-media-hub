# 技术设计

## 生成与登记

从媒体库的全量同步预览复用任务中心的 `POST /api/v1/tasks`，提交 `type=strm` 和媒体库 ID。`GET /api/v1/libraries/{id}/full-sync-preview` 使用已保存的配置和同一套 115 遍历逻辑。它检查输出路径，返回真实候选数量、有限条目样例及配置版本。确认提交后执行器重新校验当前配置和目录，再扫描并写入文件。同步历史通过 `GET /api/v1/tasks?type=strm&library_id={id}` 查询。注册 STRM 业务执行器，任务类型在历史中显示为「全量同步（STRM）」，通过媒体库入口按需运行。任务中心负责配置快照、运行状态、错误项和通知。STRM 服务负责分页列举、生成、冲突判定及产物登记，沿用现有 115 授权和请求边界。

按目录遍历并应用递归及排除配置。为目录和文件名称建立确定的输出相对路径。预览以运行账号判断输出目录或最近存在的父目录能否写入及进入。实际执行在已打开的父目录下创建缺失的目录层级。写入以已打开的输出根约束路径，拒绝越界、异常路径及不安全的链接目标。用实际目标路径协调重叠输出目录的并发写入。这避免只按媒体库 ID 加锁时两个库覆盖同一文件。

SQLite 产物登记保存媒体库 ID、115 账号、源文件 ID 和位置、产物 ID、输出位置、播放 URL、大小和生成时间。实际输出路径唯一。不同扩展名的云盘源文件可能映射到同一个 `.strm` 路径，处理时核对源文件身份。生成前登记写入意图，再在目标目录内暂存并发布完整文件。按完整 STRM 文本核对发布结果和旧内容，在短事务中更新登记。按 `skip` 或 `overwrite` 处理已归属的文件，遇到归属或内容冲突保留现有文件。旧版登记保留产物 ID 和播放凭据，通过原有播放路由核验本地文件。库被删除后，保留产物归属并停止解析播放。

## 列表与详情

在 OpenAPI 定义管理员只读的 STRM 列表和文件详情，列表依据媒体库 ID 过滤并在同一查询契约中返回统计。以稳定排序支持分页。文件详情按登记记录读取受限的本地内容并给出缺失或冲突状态。媒体库详情与 STRM 管理共用查询来源，通过任务状态变化刷新相关数据。保留现有 HeroUI 布局，用真实空、加载和失败状态替代管理列表与详情的演示数据。本期只开放真实实现的操作。

## 302 播放

媒体库保留 `strm_direct_domain` 配置键，界面使用「STRM 播放地址」。两种链接模式共用此项。仅填写域名或 IP 时默认使用 HTTPS，并支持显式 HTTP(S) origin。提交任务时校验地址，执行开始时从配置快照取值。沿用保留的 `/p/` 命名空间。播放凭据与管理员会话及 115 Cookie 独立，绑定到单个已登记产物。使用高熵凭据或持久化签名密钥，使应用重启后链接仍有效。原名或文件 ID 作为可读链接部分，文件身份由产物标识与播放凭据确定。

播放器发起请求时校验凭据、库归属及 115 授权身份，再调用受控的播放解析适配器。只有解析为有效的受信 115 HTTP(S) 临时链接时返回 302，禁用该响应的中间缓存。区分授权失效、源文件缺失及上游不可用。使用现有请求关联 ID 和业务日志，记录操作、结果、耗时及安全的 ID。播放凭据、Cookie、请求中的完整播放路径和临时链接均排除在日志之外。

播放适配器开发优先验证真实 115 接入。当前扫码授权是 Cookie 会话，仓库的目录浏览仅能证明枚举能力。115 开放平台另外提供下载及播放能力，是否能从当前授权取得播放器可跟随的临时链接需要单独验证。在测试库对获授权的真实样本验证可用方式和播放器请求头兼容性。若需要新增独立授权或 302 无法被目标播放器跟随，记录真实验证结果，重新确认范围。[115 授权契约](../../spec/backend/settings.md) · [115 开放平台](https://open.115.com/)

## 上线与回退

使用新增迁移。先在临时输出目录完成验证，再启用正式媒体库。回退时停止生成提交和 worker，保留数据库备份、已有产物和归属记录，以便重新上线时核对。业务实现保持 Go 与 TypeScript 可读，注释用于说明写入恢复、并发及上游协议等非显而易见的边界。

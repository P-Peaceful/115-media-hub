# 媒体库 STRM 生成与产物登记

## 目标

在媒体库的「全量同步」中生成 STRM，从任务中心查看处理结果，再从该库详情进入对应的真实产物列表。用真实的 115 源文件完成一次 302 播放验收。

## 当前基础

- 媒体库已持久化 115 目录、输出路径、子目录及排除规则、STRM 开关、现有文件策略与链接配置。[媒体库契约](../../spec/backend/media-library.md)
- 115 服务支持分页目录浏览。任务中心支持持久化任务、进度和错误记录，应用启动时的业务执行器注册表为空。[115 目录浏览](../../spec/backend/cloud-drive.md) · [任务中心契约](../../spec/backend/task-center.md)
- 媒体库详情的 STRM 统计与 STRM 管理清单目前使用演示数据。[已归档的 STRM 前端演示](../archive/2026-11/11-21-strm-management/prd.md)

## 首期范围

| 需求 | 行为 |
| --- | --- |
| R1 全量同步 | 通过媒体库的「全量同步 → 执行预览 → 确认执行」提交。预览按已保存的扫描范围读取 115，显示视频和有效候选数量、源路径样例及本地输出目录状态。启用库、开启 STRM、选择「302 代理」、填写播放地址并通过预览后可以提交。任务按执行开始时保存的配置浏览源目录、生成 UTF-8 STRM，并在任务中心显示进度、生成、跳过和失败结果。取消独立的 STRM 生成入口。 |
| R2 产物归属 | 产物记录关联媒体库、115 账号、源文件 ID 和输出路径。源文件身份与本地路径归属用于处理冲突。已登记产物按现有文件策略处理，本地修改通过播放链接内容比对识别。 |
| R3 真实清单 | 媒体库详情统计、STRM 管理列表及文件详情读取同一份登记数据。「查看 STRM」按媒体库 ID 打开管理列表。缺少检查结果时显示未检查，列表提供真实空状态和请求错误状态。 |
| R4 302 播放 | STRM 使用媒体库保存的「STRM 播放地址」生成稳定、播放器可达的应用 URL。302 代理与直连共用此配置。请求时校验独立的播放凭据，再从绑定的 115 授权即时获取临时链接并返回 302。媒体库表单的默认「302 代理」及已保存的原名／文件 ID 格式参与链接生成。[架构基线](../../spec/guides/project-baseline.md) |

## 验收

- **AC1 对应 R1。** 小型测试媒体库通过全量同步首次生成后，任务结果、实际文件和登记记录一致。分页、子目录与排除规则生效，部分失败能定位到对应项。
- **AC1 执行预览。** 预览读取 115 并报告真实候选，取消预览时输出目录和任务历史保持原样。目录可创建时确认同步后创建并写入。目录已被文件占用或父目录不可写时，在确认前显示具体原因。
- **AC2 对应 R2。** 同一配置重跑无重复登记。已有文件策略、路径冲突、写入中断后的重跑和外部修改均有可验证结果。删除库配置继续保留本地及 115 文件。
- **AC3 对应 R3。** 媒体库详情统计等于按库筛选后的 STRM 清单总数。详情可查看已登记文件的实际内容，文件缺失时有明确提示。UI 使用现有组件库并适配深浅主题。
- **AC4 对应 R4。** 合法播放器请求跟随 302 后取得源媒体，至少用一个授权的真实 115 样本验证实际播放。未授权、文件缺失及上游故障可区分。日志可按任务和请求定位，且排除 Cookie、播放凭据和临时链接。

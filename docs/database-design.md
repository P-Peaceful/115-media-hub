# 115 Media Hub V1.0 数据库设计（单人工具精简版）

日期：2026-10-25。状态：设计评审稿。本版按用户最新要求，将此前 39 张表、515 个字段收敛为 **17 张表、227 个字段**。当前仅更新设计材料，不执行应用迁移。

产品按一个人使用、一个应用实例运行设计，不建立用户体系。数据库只保存需要跨重启追溯的业务事实，配置、临时检测和可重建缓存不再各自拆表。字段定义见 [字段字典](database-dictionary.md)，建表定义见 [SQL 草案](database-schema.sql)。

## 1. 保留的核心表

| 数据域 | 表 | 持久化原因 |
| --- | --- | --- |
| 配置对象（2） | connections、libraries | 外部连接和媒体库业务配置 |
| 来源与产物（3） | source_nodes、library_files、strm_artifacts | 稳定来源、播放资源 ID、产物归属和最后写入摘要 |
| 扫描证据（2） | scan_directories、scan_entries | 目录是否读完及本次实际发现的文件，不凭漏扫推断删除 |
| 预览与任务（5） | operation_previews、job_plans、job_runs、job_items、job_effects | 预览、计划、启动快照、逐项结果和外部操作核验 |
| 海报墙（2） | media_items、media_file_links | 离线缓存以及分集、文件版本的可执行映射 |
| 元数据回传（2） | metadata_files、metadata_decisions | 目标映射、共同基线、冲突决议和另存目标 |
| 清理恢复（1） | quarantine_records | 隔离位置、原路径、归属及最终恢复结果 |

## 2. 删除、合并与移出数据库的部分

| 原设计 | 精简后处理 |

| created_by、decided_by、resumed_by 等操作人字段 | 删除；仅记录手动、计划、恢复等触发来源，不记录用户身份 |

| conflict_decisions | 收敛为 metadata_decisions，保留不同内容组合的已完成决议和副本目标 |

明确取舍：不提供数据库用户/会话管理、任意规则历史回滚、完整观察历史数据库检索、逐条播放凭据管理和数据库日志检索。历史运行、实际副作用、冲突决议和隔离记录仍可追溯。没有把整库扫描结果、任务项或文件历史改成无限增长的 JSON 数组。

## 3. 非数据库数据如何保存

| 保存位置 | 内容 | 行为约定 |
| --- | --- | --- |
| 配置文件/环境变量 | 管理员用户名和密码、独立播放密钥、时区、并发、节流、重试、默认白名单和部署根目录 | 管理员凭据只通过部署配置提供，不进日志；环境覆盖项不通过 UI 静默改写；库规则仍在 libraries |
| 内存 | 管理会话、资源锁、健康检测、短期播放地址及请求缓存 | 重启失效/丢弃；任务核验后再重建锁；不能默认检测通过 |
| 缓存目录 | 海报等可重建文件 | 清缓存不删除来源身份、产物归属或回传基线 |
| 日志目录 | 运行 JSONL、关键操作审计 JSONL、诊断报告 | 带 run/item/asset 关联 ID；独立轮转，展示、复制和导出同样脱敏 |
| 备份目录 | SQLite 一致性快照、配置副本和版本化 manifest | 数据库快照会包含明文连接凭据；备份访问与隔离要求需明示 |
| 独立状态文件 | 恢复阶段、包摘要、环境核对及是否等待恢复自动策略 | 原子写入，不被恢复包覆盖；损坏或恢复未完成时阻断自动清理/覆盖 |

管理员不落库不等于取消管理入口保护。保留一个配置密码与内存会话，改密码或重启清空会话即可；不引入角色、权限和多用户关联。播放认证使用独立配置密钥，从稳定 asset_id 派生可验证入口，支持全局轮换代次撤销，不复用管理会话，不把 115 登录凭据写进 STRM。轮换前预览受影响文件并受控重写；不额外建设逐 token 管理功能。

现有程序仅实现基础 YAML 配置加载；上述密码、可写业务配置、文件审计和恢复状态文件是后续实现契约，不能当作已实现功能。

## 4. 简化后仍需满足的业务契约

### 4.1 SQL 与代码的职责

沿用本地 SQLite、WAL、单连接与 goose。SQL 不声明外键或 CHECK，只保留 PRIMARY KEY、UNIQUE、NOT NULL、默认值和必要索引。关联存在性、跨库归属、值域、JSON 结构、合法状态及删除依赖由 Service 在短事务内校验；迁移、导入、恢复和维护入口也必须遵循。现有 foreign_keys=ON 连接选项保持，无声明就不会产生业务外键。

外部 ID 使用 TEXT，未知大小/未知总数使用 NULL，时间为 UTC Unix 毫秒。JSON 必须有 schema_version 和对应 Go 类型；身份、索引、分页和幂等字段保持独立列。不能用模糊标题决定文件写入目标，也不能把不存在的 CHECK 误当成安全保证。

### 4.2 当前配置与历史运行

libraries 保存当前配置，四种路径分别保存：网盘来源根、工具输出根、媒体服务访问根、元数据读取根。过滤、命名、回传规则及绑定使用所属对象内的有类型 JSON。连接凭据为服务端使用的明文 JSON；数据库及备份按敏感凭据保护，能力 JSON 记录各能力结果与时间，上传受限不阻断浏览。

任务创建时保存解析后的完整配置、全局继承值和实际范围；编辑库配置不改变已创建任务。单实例内串行保存当前配置，来源/输出/命名变更仍需预览。旧运行依据自身快照解释。库只保留启用/停用状态；物理删除前由代码检查并清理依赖，历史运行依据自身快照保留所需事实。输出根冲突、嵌套、符号链接及挂载别名仍须串行检测。

### 4.3 稳定身份、扫描与安全移动

source_nodes 身份为连接 ID + 远端稳定 ID。library_files 是每库每来源的永久 asset_id，同来源在不同库分别管理；来源、规则、本地事实不混为一个状态。strm_artifacts 保留实际输出路径、最后工具写入 hash 和最近观察 hash。用户修改时保留原文件，不能直接更新最后写入基线后宣称安全。

扫描批次使用 job_runs.id；scan_directories 保存目录分页与一致性证据，scan_entries 保存本次实际观察。缺失判断必须使用本次匹配范围/规则的完整覆盖，不能用旧成功批次或全局 last_seen 代替。失败、漏页、未知、规则排除、移出范围与真实缺失分别处理。证据未知或突然大量消失时阻断清理。

移动先写新位置并核验，再处理旧文件；旧文件未确认移除时 retired 也保留 path_reserved。扫描根外的临时目录应与最终输出在同一文件系统；跨设备复制不能冒充原子 rename。历史旧路径从保留产物和任务/effect 追溯，不再另建来源路径历史表。

### 4.4 预览、计划、执行与恢复

operation_previews 记录配置、范围、证据摘要、有效期和消费状态，明细存生成预览的 job_items。执行时把选中项复制到新运行，parent_item_id 保留来源。预览的“计划新增/跳过”等结果不等于文件实际写入成功。确认时复核当前配置摘要、来源、摘要和归属；消费预览与创建任务在一个事务内完成，request_key/request_hash 防重复提交。

job_plans 与 job_runs 分开，enabled 用于停用计划，不取消当前运行；积压/停机漏跑最多合并一次待执行意图。保留九状态 queued、running、retry_wait、cancelling、succeeded、partial、failed、cancelled、interrupted，核验属于阶段。总数未知不显示百分比；取消由执行器确认，已完成操作不自动回滚。仅重试失败项创建新运行，保留原运行、父项和已成功结果。

job_effects 不能因单人使用而删除：上传或写文件时仍可能断电。外部操作先保存 prepared，结果不确定记 unknown，核验真实目标才 verified；prepared 也可能已经执行，应先核验再重试。幂等键包含逻辑 operation_id、目标、动作、内容和预期版本；同操作重试继承 ID，独立修复使用新 ID。实际副本、覆盖备份和恢复结果写进 effect。

无需数据库锁表和分布式租约。单实例 Worker Pool 使用内存锁覆盖实际输出根/路径和远端目标，按连接节流；任务领取仍为条件 UPDATE + RowsAffected。启动先停止新写入，标记旧未完成运行已中断，核验未完成 effects，再恢复调度和锁；未知外部操作未解决前不允许冲突写入。工具锁无法阻止外部程序写网盘。

### 4.5 回传与海报墙

metadata_files 合并当前映射、最近观察和最后共同基线，持久锚点仍是来源文件/目录，不依赖媒体缓存。剧/季通用伴随文件可挂目录，同名 NFO/字幕必须有具体视频和 STRM 反向命名依据。本地碰撞后缀不能直接成为网盘目标文件名。

观察 JSON 保存两次本地摘要/大小/时间、完整可读与基本内容校验；远端分别保存存在/缺失/未知、摘要算法、版本及检查时间。共同基线只保存已核验相同的内容与目标身份，不把“保留远端”的不同内容写成一致基线。历史观察必要时从任务项/effect 查，不再全量独立保存。

metadata_decisions 保存内容组合 fingerprint、选择及已核验实际目标。另存成功保存副本稳定 ID、父目录、文件名与摘要；相同组合不重复另存，任一侧变化重新比较。多个库/版本竞争同目标仍须先解决冲突并互斥。覆盖要求身份明确、备份可恢复且已核验，有可靠条件写入则绑定版本，没有则禁止自动原位覆盖。响应成功但核验不足不能推进基线。

media_items 保留电影/剧/季/集缓存，图片引用并入 JSON；media_file_links 仍是独立的多对多文件映射，支持分集、多版本、分段。未匹配条目的文件仍可从 library_files 查到；离线保留缓存和刷新时间。海报 API 可用不等于真实 NFO/图片已落地。

### 4.6 隔离、日志与备份

默认只清理已登记且未被用户修改的 STRM，不带走 NFO/字幕/图片。quarantine_records 保留原路径、隔离位置、摘要、原因、到期及最终结果；每次恢复尝试走任务项/effect。原位占用默认保留现有文件，替代路径重新核验归属与范围；到期不等于已经永久删除。

普通日志和关键操作审计使用独立文件与轮转策略。日志带操作、范围、结果及关联 ID，复制和导出同样脱敏。文件审计不能伪装成与数据库事务原子提交；实际文件/上传效果以持久 effect 为准，审计故障可见并阻断需要审计的破坏性动作。不承诺数据库全文检索。

恢复先暂停任务并在数据库外原子写门禁标记，再导入一致性快照；标记不随备份覆盖，重启仍有效。旧预览失效，旧 effects 核验；授权、挂载、读取、隔离/临时目录检查通过后由用户恢复自动策略。配置、来源身份、映射、基线、决议、隔离及必要任务状态必须进入备份；真实隔离文件和覆盖备份的外部依赖列入 manifest。

## 5. 需求依据与取舍

用户 2026-10-25 的“单人使用、工具类型、管理员不落库并进一步精简”优先于旧方案的管理员/会话/身份字段设计；此前“不使用外键和 CHECK”的决定继续有效。

业务范围仍参考 [功能文档](https://app.notion.com/p/401138389edc81298a1aeb6012d4f8e8)、[后端架构](https://app.notion.com/p/401138389edc811fabfcefbf05f26845)、[前端架构](https://app.notion.com/p/401138389edc814fb54be80c599600ef)、[UI 文档](https://app.notion.com/p/401138389edc8143b487f666a58004f4) 和 [Canva 38 个视图](https://www.canva.com/d/gqYuehW7cYo2nn-)。旧文档中单管理员落库和独立审计表的保存方式由本次决定替代，不宣称原始文档已改写。

精简的是保存方式，不默认删掉海报墙、回传、重启恢复或安全清理。只支持一个应用实例；未来多进程/远端执行器需重新设计互斥，不能启动多个容器共享库。业务表尚未实现，本次不涉及真实用户数据迁移；旧版 25/26 项检查不再作为本版结论。

## 6. 验证与实现边界

此前 235 字段草案曾通过 36 项临时 SQLite 结构检查；本次移除版本及逻辑删除字段后，字段数为 226，旧检查结果和索引数量不再代表当前草案。此次仅做静态一致性整理，未重新执行 SQLite 检查。

这些是设计验证，不证明尚未编写的 Service 校验、配置管理、文件审计、真实上传、客户端播放或门禁已实现。外部稳定身份、条件写入和跨文件系统布局仍需样本验收。后续业务实现另行规划，通过 goose 迁移；当前 SQL 仍是 docs 下的评审草案。
